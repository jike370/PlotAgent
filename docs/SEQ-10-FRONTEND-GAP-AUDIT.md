# SEQ-10 前端差距审计：参考 PLOT 与当前 PlotAgent v3

> 状态：SEQ-10 入口审计完成，蓝图冻结仍在进行中
> 日期：2026-08-07
> 对比对象：`http://127.0.0.1:8000/`、`C:\Users\pc\Desktop\PLOT-windows-local` 与 `D:\plotv3`
> 目的：判断参考前端中哪些模式值得吸收、当前 v3 哪些能力必须保留，以及完整生产前端重做前必须补齐哪些产品与交互契约

## 1. 结论

参考前端不应成为 PlotAgent 新前端的结构母版。

它的优势是单次任务节奏短：新建任务、上传、选择图形、确认方案、得到图、编辑和恢复版本都能在一个连续界面中理解。它的局限也很明确：任务近似一张图，模型配置和 Debug 长期进入主工作区，右侧版本栏常驻，缺少项目、资源、批量审阅、作用范围、ChangeSet、Origin 与科研复现语义。

当前 v3 的领域基础更接近目标产品。项目、本地优先、原始数据只读、数据集、明确选图、字段映射、43 图准入、版本、Core 预览、强类型编辑、批次、组合图和 Origin 降级均已有真实对象或接口。现阶段的问题不是缺少功能入口，而是这些能力尚未被组织成一条可信、连续、批量优先的用户任务流，并且生产界面仍混有未接入动作、旧文案和演示数据。

SEQ-10 因此采用以下方向：

- 保留 v3 的领域对象、桌面架构、本地信任边界和“校准工作台”视觉方向。
- 借鉴参考页的提案确认卡、即时任务反馈、结果附近版本入口和编辑撤销/重做节奏。
- 不照搬参考页的三栏常驻结构、单图任务模型、扁平图形下拉、常驻模型配置、Debug、浏览器下载语义和分析指标卡。
- 前端重做围绕三个工作区：默认对话、全窗口批量审阅、全窗口聚焦编辑；组合图继续使用全窗口专业模式。
- 在真实批量纵向链路和最小领域契约稳定前，只冻结蓝图和基础原语，不把临时对象或 mock 操作接入生产新壳。

## 2. 两个前端的本质差异

| 维度 | 参考 PLOT | 当前 PlotAgent v3 | SEQ-10 判断 |
| --- | --- | --- | --- |
| 产品容器 | 任务近似单图 | 项目包含数据、图、批次、组合和版本 | 采用“项目 → 多对话 → 多产物”，不采用“一任务一图” |
| 主界面 | 左任务、中对话、右版本/Debug 三栏常驻 | 左项目/对话、中工作区，无常驻右栏 | 保留无常驻右栏；版本、资源、参数按当前对象打开 |
| 首次使用 | 先新建任务，再面对选图和配置 | 示例、导入、打开项目三个入口 | 保留 v3 三入口，首次工作不暴露 Provider/Token/配置路径 |
| 图形选择 | Composer 内 9 项英文缩写下拉 | 43 图图形库、搜索、兼容性和能力信息 | 保留明确选图；Composer 显示当前选择，完整选择进入图形库 |
| 数据表达 | 提案内展示列与预览 | 数据集、字段、单位、质量、映射独立成对象 | 用统一对象语法保留可追溯性，默认只展示摘要 |
| 执行确认 | 紧凑 ProposalCard，确认后绘图 | 数据对象、选图、映射按序展开 | 吸收提案卡节奏，承载一次映射、警告和批量资格 |
| 批量 | 无独立审阅工作区 | 有 Batch API/工作区，但当前是状态列表且需先画单图 | 重做为可直接进入的真实缩略图审阅主链路 |
| 自然语言改图 | 主要作用于当前结果/版本 | 已有目标和范围概念，结果尚不够可核对 | 指令前只显示真实可用范围；指令后必须展示 ChangeSet |
| 精确编辑 | 大型模态编辑器 | 全窗口 FocusEditor、强类型 Patch、能力白名单 | 保留全窗口模式，删除或接真所有假动作/硬编码数据 |
| 版本 | 常驻右栏恢复 | 对象与聚焦编辑内版本 | 结果旁显示当前版本，完整时间线按需打开 |
| 导出 | 结果链接下载 | PNG/SVG/OPJU、Origin 状态和降级 | 使用 ExportRecord、范围、版本和 Origin preflight，不退化为下载链接 |
| 模型服务 | 左栏内联配置 | 独立 Provider dialog、凭据库和出境确认 | 继续放在设置/Agent 状态中，不进入主导航内容流 |
| 科研边界 | 源码含 AnalysisCard | 明确不做通用分析/拟合平台 | 不引入分析指标卡；只表达图形不可分割的固定计算与预计算字段 |

## 3. 应借鉴与应拒绝的参考模式

### 3.1 应借鉴

1. **提案确认卡。** 执行前集中展示图形、数据摘要、字段角色、行数/系列数、警告和确认动作，减少 Agent 不确定性。
2. **即时任务反馈。** 用户发送后立即回显指令、处理状态和可折叠阶段，任务中心与对话对象使用同一套阶段词汇。
3. **版本离结果更近。** 当前版本和恢复入口应与 Plot/Batch/ChangeSet 对象相邻，而不是藏在全局设置中。
4. **编辑的即时预览与撤销/重做。** 原则保留，但必须由真实 Patch、版本和整体撤销支撑。

### 3.2 不应照搬

1. 常驻右侧版本/Debug 栏；它会长期压缩画布并把内部诊断置于科研对象之上。
2. 常驻左侧模型配置；Provider、Base URL、Token 和配置文件路径不属于首次任务主线。
3. “任务等于一张图”的结构；一段对话必须允许导入多份数据并创建多个批次或图。
4. 扁平图形下拉；它不能表达 43 图、字段要求、兼容性、首批 14 图批量资格和 Origin 等级。
5. AnalysisCard 与通用计算承诺；这与已冻结的非分析平台边界冲突。
6. 浏览器式 SVG/PNG 下载；桌面导出必须记录范围、来源版本、格式、状态和 OPJU 环境结果。

## 4. 当前 v3 必须保留的能力

- 本地 Windows 桌面运行、无需账号、本机项目、原始数据只读。
- 示例项目、导入自己的数据、打开 `.plotproj` 三个首次启动入口。
- 项目、数据集、来源版本、字段逻辑/物理类型、单位和质量摘要。
- 用户明确选图、43 图正式准入过滤、不兼容图仍可见、一次字段映射。
- Core 创建真实 PlotSpec/预览、强类型 PlotPatch 与图形版本。
- 任务事件和取消、Core 失联、Agent 离线、Origin 不可用仅禁用 OPJU。
- 全窗口聚焦编辑、通用/专属 capability、Origin 对齐色板与符号。
- 批次和组合图领域能力、Figure 固定引用 Plot 版本、PNG/SVG/OPJU 范围导出。
- 自定义模型服务的凭据库写入与数据出境确认；它不影响本地手动绘图。

## 5. P1 缺口

### P1-1 项目内对话还不是连续、可恢复的任务历史

当前左栏每个项目只有静态对话表达，中部主要显示当前对象状态。用户无法从一条时间线理解“哪条指令产生了哪个数据集、图、批次、版本或导出”。

SEQ-10 要求项目包含多对话；对话共享项目资源，但不自动继承其他对话全文。时间线统一嵌入 Dataset、Mapping、Batch、Plot、ChangeSet、Figure 和 ExportRecord。

### P1-2 批量仍是单图后的附属流程

当前批量入口依赖先完成单图，`BatchInspector` 以状态行而不是真实缩略图为主，缺多选、异常标记、排除导出、失败项局部重试和批量自然语言修改。

SEQ-10 要求多数据在对话中直接选择首批 14 个批量合格图形，确认一次字段映射后进入全窗口审阅。其余 29 图继续支持单图，但入口必须明确说明未通过首批批量资格。

### P1-3 作用范围与 ChangeSet 尚未闭环

输入框可以表达当前图、选中图和批次，但部分不可用范围仍可见；Agent 结果没有完整列出来源版本、已应用、跳过/不支持、失败、结果版本与整体撤销。

SEQ-10 要求指令前只显示当前上下文真实可用的范围；指令后用结构化 ChangeSet 核对实际结果。失败目标不改原版本，同一次 ChangeSet 只提供一次整体撤销。

### P1-4 旧文案、假动作和演示数据破坏科研信任

现版仍能找到“52 项”旧口径、拟合式描述、固定批次/版本/点数、模拟失败项，以及没有真实行为的搜索、设置、帮助、比较、导出或工具按钮。科研用户会把每个数字和按钮视为事实。

SEQ-10 要求所有设计元素在实现清单中标记为 `真实接入`、`等待 SEQ-30/40` 或 `不进入生产`；发布界面只显示真实能力，不能用 disabled 占位按钮预告未来功能。

## 6. P2 缺口与工程质量

1. **可读性。** 当前大量 7.5–10px 字号、约 30px 控件和高密元数据不适合长时间科研工作。默认正文目标不低于 12px，关键标签不低于 11px，主要操作热区接近 36–40px；哈希、ID 和实现版本进入“详情”。
2. **弹层焦点。** 浏览器实测 Provider 与任务弹层打开后焦点仍停留在背景触发按钮。新壳必须统一实现焦点进入、Tab 圈闭、Escape 关闭和关闭后的焦点恢复。
3. **状态语义。** 空状态、处理中、部分成功、失败、NeedsInput、Unsupported、版本冲突、撤销、离线和 Origin 不可用需要统一对象卡，而不是散落通知或错误码。
4. **上下文帮助。** 帮助应出现在字段映射、图形要求、警告、Origin 状态和快捷键附近；无内容的“帮助与反馈”入口不进入生产。
5. **批量列表视觉。** 检测器在 `batchInspector.css` 命中单侧 3px 状态色条；新审阅页改用缩略图边界、图标和文本共同表达状态，避免模板化侧色条。
6. **桌面边界。** 当前 Electron 最小窗口是 1100×720，SEQ-10 仍需补齐 1920×1080 下 100%/150% DPI 的布局证据，而不是转向移动端响应式。

## 7. 三工作区与导航基线

```text
项目 / 对话侧栏
  -> 对话工作区（默认）
     -> 图形库覆盖层（选图后返回原对话位置）
     -> 项目资源覆盖层（按需）
     -> 批量审阅工作区（全窗口，返回来源 Batch 对象）
     -> 聚焦编辑工作区（全窗口，返回来源 Plot 对象）
     -> 组合图工作区（全窗口，只承载第一阶段真实固定布局）
```

主对话不出现常驻版本栏、资源栏或参数栏。所有全窗口工作区都必须保留明确返回来源对象的路径，不能返回一个模糊首页。

### 7.1 第一阶段主链路

```text
创建/打开本地项目
-> 新建或打开项目内对话
-> 导入多文件或多工作表
-> Dataset 对象确认结构
-> 用户明确选择一个图形
-> Mapping 提案确认一次字段映射
-> 单数据：生成 Plot
-> 多份完全同构数据且图形已通过批量资格：创建 Batch
-> 全窗口真实缩略图审阅
-> 选择当前图 / 选中图 / 整个批次
-> 自然语言修改
-> 核对 ChangeSet
-> 导出并生成 ExportRecord
```

## 8. 一致对象语法

| 对象 | 默认可见 | 按需详情 |
| --- | --- | --- |
| Dataset | 名称、版本、只读、行/字段、单位/质量摘要 | 路径、hash、解析细节、完整字段表 |
| Mapping | 图形及版本、必需角色、当前字段、确认状态 | 可选角色、语义签名、PreparationSpec |
| Batch | 类型、批次版本、成员数、完成/失败/需输入、当前选择 | 完整任务日志、capability 分组 |
| Plot | 图形、Plot 版本、绑定数据版本、真实预览、警告 | RenderPlan、hash、详细参数 |
| ChangeSet | 来源版本、范围、接受/跳过/失败计数、结果版本、撤销 | 每个 Patch 的完整机器字段 |
| ExportRecord | 格式、范围、版本、状态、文件名、Origin 等级 | artifact hash、manifest、环境详情 |

## 9. 状态矩阵

| 状态 | 默认表达 | 必须提供的动作 |
| --- | --- | --- |
| 空状态 | 三个首次入口或对象级空说明 | 与当前上下文匹配的唯一主动作 |
| 处理中 | 对话对象和任务中心使用同一阶段与进度 | 可取消时显示取消；不可取消时说明提交边界 |
| 部分成功 | 成功缩略图保留，失败项原位显示原因 | 仅重试失败、排除失败后继续导出 |
| 失败 | 原因、影响范围和恢复建议，错误码折叠 | 重试、返回修正或打开诊断 |
| NeedsInput | 一次一张卡、最多三个问题、保持作用对象 | 回答后继续原任务或取消 |
| Unsupported | 不支持内容、原因、仍可执行内容 | 返回修改请求，不创建新版本 |
| 版本冲突 | 当前版本与预期版本对比 | 刷新、另存为新操作或取消 |
| 撤销 | ChangeSet 级撤销结果和恢复版本 | 查看被恢复对象 |
| Agent 离线 | 明确只影响自然语言能力 | 继续手动导入、绘图、编辑和导出 |
| Origin 不可用 | OPJU 不可用原因 | 保留 PNG/SVG，提供 Origin 排障 |

## 10. 客观检测与限制

- 参考页运行于 1280px 和 900/700px 视口；低于 1100px 会隐藏右栏。初始页没有 `aria-live`、`role=status`、`role=alert` 或 `aria-busy`，但焦点轮廓可见。
- 当前 v3 Web 运行页能验证应用壳、Core 失联、Provider dialog 和任务抽屉；由于没有 Electron bridge，导入、绘图、批量和聚焦编辑的运行态以生产源码和既有截图为降级证据，不能声称已通过真实浏览器链路。
- Impeccable 确定性扫描：参考构建产物 3 个文件、0 条命中；v3 renderer 27 个文件、1 条 `side-tab` 命中。参考页只有编译后的 bundle，0 条命中不等于没有产品或可访问性问题。
- 浏览器环境拒绝可变脚本注入，因此未显示 detector overlay；结论来自 DOM/ARIA、截图、确定性扫描和源码，不声称已完成 overlay 验证。
- 当前检查发现 dialog 焦点进入/圈闭证据不足；应用源码已有全局 Escape 处理、部分 `aria-live`、可见焦点和 reduced-motion 基础，应保留并统一为基础控件原语。

## 11. SEQ-10 后续产出

本审计只完成 SEQ-10 的入口比较，不代表阶段完成。进入 SEQ-20/30 之外的前端实现前，SEQ-10 还需产出并确认：

1. 三工作区低保真屏幕与模式切换图。
2. 1920×1080、100%/150% DPI 基础布局与密度基线。
3. 图形选择、提案确认、批量审阅、范围修改、ChangeSet 和导出的完整交互清单。
4. 所有生产界面元素的真实接入/等待契约/不进入生产标记。
5. 对话、多对话、资源共享、版本和返回来源对象的导航规则。
6. 基础控件词汇、焦点策略、键盘路径和状态组件规范。

## 12. 本轮实施选择记录

- **选择：** 以 v3 为产品和技术基线，只吸收参考前端的局部交互模式。**原因：** v3 已有真实桌面/Core/Origin/领域契约；搬用参考结构会丢失批量、复现和本地信任语义。
- **选择：** 本轮只更新蓝图与审计，不修改生产前端。**原因：** SEQ-10 的职责是冻结 IA、对象、状态和工作模式；真实页面接入需等待最小批量纵向链路稳定。
- **选择：** 把无障碍焦点、无假动作和真实缩略图列为新壳基础门槛。**原因：** 这些问题若晚于页面迁移处理，会在所有弹层、工作区和状态组件上重复返工。
