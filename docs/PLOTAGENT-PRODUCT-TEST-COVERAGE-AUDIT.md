# PlotAgent 产品测试覆盖审计

> 状态：2026-08-21 编辑能力审计基线。
> 范围：34 个正式图类、Agent/工作流、能力目录、Windows UI、Matplotlib、Origin、持久化与导出。
> 目的：解释既有测试为何没有发现 X38 轴范围缺口，并冻结后续测试分层，避免再用某一层全绿代替产品完整性。

## 1. 结论

既有测试没有“失效”，但覆盖边界被误解了：

- 任务状态矩阵证明规划、追问、确认、执行、部分失败、修复、跳过、重新确认、取消、恢复和重启的状态转换与副作用；它不枚举图类编辑参数。
- SEQ-70 证明冻结样例中的 Agent 决策、对象绑定和恢复质量；编辑样例只覆盖少量标题与轴标题，不是 34 图编辑笛卡尔积。
- Windows 黑盒证明实际执行过的 UI 路径；此前主要覆盖创建和代表性编辑，没有逐图逐参数执行。
- 能力目录、编译器和前端都读取同一份 profile。目录漏掉 X38 `bounds` 时三层会“自洽地拒绝”，只有独立产品期望才能发现。
- 双后端共用 T1 视觉适配器，既有适配器测试证明参数可以执行，但没有证明每张图是否正确声明了该参数。

因此，测试必须同时覆盖“生命周期正确”“能力声明完整”“跨层传递正确”“双后端实际执行”四件不同的事。

## 2. 本轮审计发现与处理

| 发现 | 原因 | 处理 |
|---|---|---|
| Y 偏移堆叠线图不能设置 30–90 的 X 轴范围 | profile 漏掉 `set_axis.bounds`，Agent 和 UI 只能据目录拒绝 | X38 开放 `bounds`，新增目录、工作流编译和 UI 提交回归 |
| 双向误差棒图和误差带共用一整套误差参数 | profile 按“误差”粗粒度开放，UI 也同时提交两类参数 | K06 只开放误差棒四参数；K07 只开放误差带四参数；UI 按参数白名单渲染和提交 |
| 产品文档仍声称支持文本标注 | 旧 T1 设计稿未随产品决策收口 | 正式 profile、图形库和聚焦编辑均不开放，用户能力文档删除该项 |
| 混合图无法精确限制某个轴/系列的参数 | `EngineCapability` 目前只有图类级参数，没有目标级参数 | 记录为合同结构缺口；在引入目标级白名单前，不对 X24 等混合语义图盲目扩大能力 |

## 3. 当前公开编辑能力

以下数字由 34 个正式 `engine-profile.v1` 统计，表示 Agent、编译器和 UI 可以公开使用的能力，不表示 Origin 的全部菜单能力。

| 能力 | 图数 | 例外原则 |
|---|---:|---|
| 图标题 | 34 | 无 |
| 轴标题与可见性/刻度方向 | 34 | 无 |
| 轴范围 | 30 | K20、K21、S61 为矩阵/类别轴；X24 为混合轴合同缺口 |
| 轴尺度 | 27 | 仅在图类语义允许时开放 |
| 轴反转 | 33 | X24 暂不开放 |
| 系列样式 | 34 | 参数按图元家族不同，不代表每个系列拥有全部参数 |
| 图例 | 29 | 仅有语义图例对象的图类 |
| 数据标签 | 12 | 仅稳定支持的图类 |
| 色板/色标 | 5 | 仅色图类 |
| 误差样式 | 2 | K06 误差棒、K07 误差带 |
| 图类专属参数 | 5 | 由 profile 白名单限定 |
| 独立文本标注 | 0 | 当前产品明确不做 |
| PNG/SVG/OPJU 导出 | 34 | OPJU 仍依赖合格 Origin 环境 |

## 4. 已有测试真正证明什么

| 测试层 | 证明 | 不能替代 |
|---|---|---|
| Pydantic/Schema | 动作字段类型、范围和序列化稳定 | 某图是否应该开放该动作 |
| 任务状态矩阵 | 状态转换、确认授权、幂等、取消和恢复 | 图类、字段、样式与导出正确性 |
| Profile/Compiler | 声明的角色和参数会被接受或拒绝 | 声明本身是否完整 |
| 共享 T1 适配器 | Matplotlib/Origin 能执行公共参数 | 34 个 profile 是否都声明正确 |
| Profile renderer 测试 | 图形结构、数据绑定和若干专属语义 | 完整编辑参数组合 |
| SEQ-70 | 冻结真实模型样例的规划质量 | UI、Origin 菜单和未入样例的能力 |
| Windows UI 黑盒 | 正式入口中的实际可见行为和产物 | 未执行用例、实现内部不变量 |
| 视觉审查 | 默认态或指定编辑态的外观 | 数据绑定、状态机和恢复 |

## 5. 本轮新增的确定性门禁

1. 固定 34 图共同编辑骨架，禁止 profile 静默丢失标题、轴、系列或导出。
2. 固定轴范围、尺度和反转的完整例外集合；新增图类或修改例外必须显式更新产品期望。
3. 固定 K06/K07 的互斥误差参数集合。
4. 固定“有图例对象才有图例动作”。
5. 固定所有正式图类不开放独立文本标注。
6. 固定 X38 自然语言草稿中的 X 轴 `minimum/maximum` 可以通过工作流编译。
7. 固定前端从生成目录获得 X38 轴范围和 K06/K07 误差白名单，并只提交白名单参数。

这些门禁刻意把期望写在独立测试中，不从同一份生成目录反推期望。

## 6. 仍需分层补齐的产品测试

### P0：发布前必须

- 每个正式图类至少执行一次创建、标题、适用轴范围/尺度、一个适用系列样式、图例或明确无图例、撤销、重做和重启恢复。
- 撤销/重做必须是全量逆向：动作含任一无法从当前 PlotDocument 精确恢复的参数时，产品不得生成部分逆动作或显示可撤销状态。当前发布只承诺基础可逆参数；完整历史版本恢复作为后续架构方案保留。
- 每个公开编辑参数至少在 Matplotlib 和 Origin 各有一个真实原生对象读回；OPJU 用全新 Origin 会话重开。
- Windows UI 对每个“公开/不公开”状态各有正反例，不能只检查按钮存在。
- 导入到绘图覆盖 CSV、多工作表 Excel 和带仪器头的 TXT；类型、单位、来源身份和多源对齐均核对。
- PNG、SVG、OPJU 分别验证成功提示、文件存在、内容非空和可编辑/矢量资格。

### P1：稳定性与兼容

- Provider 超时、限流、断网、代理、无额度、坏 JSON、迟到响应和取消。
- Core/Electron 异常退出、项目锁、执行中重启、部分成功恢复和磁盘写入失败。
- 大数据量、长文本、CJK、缺失值、极值、重复类别、动态系列增删和批量任务。
- 打包产物、全新 Windows 用户、无 Origin/错误 Origin 版本和便携路径。

### P2：合同演进

- 为混合图增加“目标级参数白名单”，覆盖 X24 的三根语义轴、X36 的柱/线系列以及 X39/X40 的 connector/column 对象。
- 将需求—profile—Agent 工具—UI 控件—双后端读回—黑盒证据映射成可生成追踪表，评测只允许引用实际证据。

## 7. 发布判定

发布不能只看单一总通过率。至少同时满足：

1. 任务状态矩阵全绿；
2. 独立能力矩阵全绿；
3. 静态、类型、Schema、Python 与前端测试全绿；
4. 正式 Windows UI 冻结黑盒无产品 FAIL，未执行项明确列出；
5. SEQ-70 达到冻结门槛；
6. Origin 产物在新会话中可重开、可编辑且机械读回一致；
7. 工作树干净，源码、生成合同和用户能力文档来自同一提交。
