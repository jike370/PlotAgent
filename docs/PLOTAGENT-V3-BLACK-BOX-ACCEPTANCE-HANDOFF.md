# PlotAgent v3 Windows 黑盒验收交接

> 被测范围：34 张单图、内置 Agent、批量、版本/撤销重做、PNG/SVG/OPJU、重启恢复。组合图/K25 不再测试为成功能力，只验证不可发现和旧引用墓碑。

## 1. 冻结与环境

1. 记录 `git rev-parse HEAD` 和 `git status --short`；工作树必须符合交接者声明。
2. 只从仓库根目录使用正式 Electron 入口 `pnpm dev`；禁止浏览器预览、静态审计页或旧进程补证。
3. 关闭旧 PlotAgent/Electron/Vite/Core 进程，并确认相关监听端口释放。
4. 新建唯一项目名和全新输出目录；不得复用旧项目截图或导出。
5. 记录 Windows、Origin、模型服务、启动命令、项目名和测试数据 SHA-256。

## 2. 结果规则

- PASS：正式 UI 实际执行且结果满足预期，并有原始截图/产物。
- FAIL：实际执行后观察到产品不符合预期。
- BLOCKED：环境阻止执行。
- UNVERIFIED：未执行或证据不足。

每个用例必须填写 observation；不得用“未执行”“见单测”“源码已修”代替黑盒结果。

## 3. 批次安排

建议拆为 6 批，每批独立启动、独立报告、独立输出目录：

1. 基础与误差：折线、折线符号、散点、气泡、双向误差棒、误差带、柱状、分组柱状。
2. 柱与分布：堆积柱、百分比堆积柱、列散点、箱线、小提琴、直方、面积、日期时间折线。
3. 矩阵与结构：热图、相关矩阵、填充等值线、分面、混淆矩阵、Nyquist。
4. 扩展单图 A：垂线、棒棒糖、蜂群、浮动柱、人口金字塔、Pareto。
5. 扩展单图 B：双 Y 轴 Y-Y、双 Y 轴柱、双 Y 轴柱线、Y 偏移堆叠、线条序列、前后对比。
6. Agent/UX/恢复/导出：任务对话、确认、真实阶段、撤销重做、批量部分失败恢复、重启、PNG/SVG/OPJU。

每批执行完必须停止应用、保存报告并确认无残留产品进程。

## 4. 34 图创建门禁

每张图均需：

1. 选择与图类兼容的冻结数据表；
2. 记录字段映射截图；
3. 点击确认后获得 Plot ID 和 v1；
4. 截图确认图类身份与数据语义；
5. observation 不得为空。

特别复测：

- 双向误差棒：映射 X、中心值、X 下/上限、Y 下/上限；水平和垂直正负误差均出现。
- 误差带：X、中心、下限、上限均为必填；可选分组不得触发参数拒绝。
- 面积图：映射控件必须显示 `series_1`，并允许增加系列。
- 日期时间折线图：一列时间加至少一个系列；含文本时间列的数据不得被误判不兼容。
- 相关矩阵：两列标签加一列数值的长表可进入映射。
- 蜂群图：一列数值即可兼容，分组可选。
- 人口金字塔：类别标签位于中央轴。
- Y 偏移堆叠线图：宽表 `X + N 个 Y`，控件支持动态增加系列。
- 前后对比图：Subject 必填、Group 可选；每条连接对象身份可读。

## 5. 删除范围门禁

图形库、搜索、字段映射、Agent capability、导出入口均不得出现：

- 核密度图；
- 多面板组合图/K25；
- Kaplan–Meier 生存曲线；
- 森林图；
- 其他已删除历史图类。

旧项目引用这些 ID 时必须返回 `CHART_TYPE_REMOVED`，不得创建图、候选篮、组合工作区、近似 PNG 或 OPJU。

## 6. Agent 与交互

至少执行：

1. 用户输入明确自然语言修改，出现用户气泡。
2. Agent 显示理解/字段绑定或修改确认卡；缺信息时只追问必要问题。
3. 用户确认前 Plot 版本不变。
4. 执行中显示真实阶段，例如字段绑定、计划校验、renderer 调用、导出；不伪造百分比。
5. 完成后显示 Plot ID、版本和结果；失败显示可操作原因。
6. 一次较复杂编辑在桌面预算内得到计划或明确超时；迟到响应不得覆盖新上下文。
7. 未明确图类的“画一张图”要求选择图类，不得擅自推荐并执行。
8. 对标题/轴/系列/图例的可逆编辑分别执行一次撤销和重做，确认每次形成新版本。

## 7. 批量与恢复

- 创建至少 3 成员批次，其中 1 项故意失败；成功项保留。
- 恢复时只执行失败或未开始项，不重复成功项。
- 完全关闭应用和开发进程后重启；项目、数据身份、最近 Plot ID/版本与预览恢复。
- 干净重启不得出现“工作区已有写入器”。

## 8. 导出

- 至少导出一张普通 XY、一张柱/分布、一张矩阵/场、一张双轴图的 PNG 和 SVG。
- 至少选择 4 个不同 Origin 模板家族导出 OPJU。
- 每次导出成功后 UI 显示明确成功消息和产物名/路径。
- OPJU 必须非空；用 OriginPro 重开，检查图页和实际数据工作表存在且可编辑。
- 在 Origin 中修改一个数据值或原生样式，保存并再次重开，修改保持。

## 9. 输出目录

```text
<run-root>/
├── PLOTAGENT-V3-BLACK-BOX-REPORT.md
├── blackbox_cases.csv
├── run-metadata.json
├── evidence/
│   ├── charts/
│   ├── agent/
│   ├── batch/
│   ├── restart/
│   └── export/
└── exports/
    ├── png/
    ├── svg/
    └── opju/
```

CSV 最少字段：`case_id,domain,status,expected,observation,evidence,artifact,notes`。

## 10. 最终汇总

必须分别报告：

- 34 图 PASS / FAIL / BLOCKED / UNVERIFIED；
- 删除图类不可发现与墓碑结果；
- Agent/UX；
- 批量恢复；
- 重启恢复；
- PNG/SVG；
- OPJU 可编辑性；
- 产品 FAIL、环境 BLOCKED、证据不足 UNVERIFIED；
- 总体结论。

只有 34 图和所有 P0 工作流在正式 UI 中有充分证据时，才可宣称完整黑盒达标。
