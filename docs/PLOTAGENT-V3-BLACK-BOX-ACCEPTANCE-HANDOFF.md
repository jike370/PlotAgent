## 1. 验收目标

本轮要回答的不是“代码是否有测试”，而是测试人员能否只通过正式Windows桌面界面完成以下闭环：

1. 新建项目并导入数值数据；
2. 从正式图形库选择图形并完成字段映射；
3. 创建和修改图形，且修改前后版本可识别；
4. 使用自然语言生成可核对的绘图或改图计划；
5. 完成批量绘图、部分失败恢复和多面板组合；
6. 关闭并重启桌面应用后恢复项目、数据身份和最近图形；
7. 导出PNG、SVG和可在Origin中继续编辑的OPJU；
8. 正式目录严格为35图，已删除图形不再出现在任何可发现入口。
9. 用户消息、Agent追问/确认/进度/结果在同一对话时间线闭环，可逆编辑可撤销/重做，并能比较真实相邻版本。

此前35图视觉审计已由产品负责人确认通过，但该结论不能替代本轮桌面黑盒。静态HTML审计页、源码、单元测试、开发者说明和历史截图均不能作为本轮PASS证据。

## 2. 冻结基线与启动入口

### 2.1 必须记录的基线

在 `D:\plotv3` 中执行只读检查：

```powershell
git rev-parse --short HEAD
git status --short
git diff --exit-code db52fce -- . ':(exclude)docs/**'
```

预期：

- 记录实际HEAD；非 `docs/**` 文件相对 `db52fce` 无差异，只允许其后的纯 `docs/**` 交接修正；
- `git status --short` 无输出；
- 上述 `git diff` 退出码为0；
- 若任一项不符，停止验收并记 `ENV-01 = BLOCKED`，不得自行切换提交、还原文件或继续以其他代码状态测试。

### 2.2 唯一正式源码测试入口

```powershell
pnpm dev
```

必须操作由该命令打开的PlotAgent Electron桌面窗口。以下入口不属于本轮黑盒：

- `pnpm dev:web`；
- 浏览器预览；
- `build/visual-audit` 下的静态审计页；
- Python开发脚本或测试脚本；
- 直接调用本地服务、数据库或内部接口。

如当前终端找不到Node/pnpm，可在不修改仓库的前提下临时设置：

```powershell
$env:PATH='C:\Users\pc\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin;C:\Users\pc\.cache\codex-runtimes\codex-primary-runtime\dependencies\bin\fallback;' + $env:PATH
pnpm dev
```

当前仓库没有已经签名、可替代上述入口的正式Windows安装包。若测试人员改用另行提供的安装包，必须记录安装包绝对路径、SHA-256和版本，并建立独立报告，不能与本轮结果合并。

## 5. 结果状态与证据规则

每个案件只能取以下一种状态：

- `PASS`：通过正式桌面界面执行了完整步骤，观察结果满足全部预期，且原始证据充分。
- `FAIL`：实际观察到产品行为不符合任一必需预期。
- `BLOCKED`：环境、权限、Origin或模型服务使步骤无法执行；不是产品通过或失败。
- `UNVERIFIED`：未执行、步骤不完整或证据不足。

“执行过”“没有报错”“文件存在”“能打开”均不自动等于PASS。每个PASS至少需要：

1. 完整桌面窗口截图，能识别项目、数据表、图形和当前状态；
2. 必要时提供导出产物；
3. 记录实际观察值，而不是只抄写预期；
4. 涉及重启时记录重启前后项目名、数据表名、plot/figure ID与版本；
5. 涉及OPJU时提供Origin原生窗口中的图页和数据表证据。

## 8. 第三阶段：手动编辑与Agent编辑

### 8.1 共同编辑动作

从不同模板家族选择代表图，至少覆盖：K02、K08、K13、K20、K22、K24、K25、X23、X39。对产品实际显示为可用的动作逐项执行：

1. 修改中文标题“中文标题：温度响应”；
2. 修改适用的X/Y轴标题、范围、反向或Log10；
3. 修改一个明确系列的颜色、线宽、线型、符号或填充；
4. 显示/隐藏图例并改变适用的位置；
5. 修改图形详情中实际开放的专属参数；
6. 添加一条可见文本标注；
7. 确认每次成功修改产生新版本，未修改其他对象。

不要求每张图开放相同动作。界面未声明的参数不应以“无反应”处理，而应保持不可用或给出明确说明。

### 8.2 Agent案件

模型服务可用时执行：

| 案件 | 请求 | 预期 |
|---|---|---|
| AG-01 | “把当前图标题改成中文标题：温度响应” | 计划目标明确；确认前无副作用；确认后只改标题并生成新版本 |
| AG-02 | “把当前图的Y轴改为log10，其他不变” | 只作用Y轴；不误改X轴、图形或数据 |
| AG-03 | “把第二个系列改为红色虚线，图例放右侧” | 绑定第二系列；样式和图例共同生效，其他系列不变 |
| AG-04 | “用这些数据画一张图”且未说明图类 | 必须询问需要的图形，不得自行猜图 |
| AG-05 | 在K06上明确指定X、中心、X误差、Y误差 | 计划保留四个角色，不交换或丢失双向误差 |
| AG-06 | 指向不存在、已删除或陈旧对象 | 明确拒绝；项目版本不增加 |
| AG-07 | 提交复杂中文复合编辑 | 35秒内返回计划、必要追问或明确超时；桌面层不应提前截断 |
| AG-08 | 超时或失败后切换数据/图形并发起新请求 | 旧响应不得覆盖新目标；成功后陈旧错误不继续显示 |

若模型服务不可用，以上案件逐项记 `BLOCKED`，不能把本地服务绿色、手动编辑成功或程序测试当作Agent PASS。

### 8.3 任务型对话与版本交互

以下案件必须使用正式对话主界面和聚焦编辑界面，不得以源码、单测或静态页面代替：

| 案件 | 操作 | 预期 |
|---|---|---|
| UX-01 | 新项目尚无数据时发送“把标题改成测试” | 用户原文保留为右侧气泡；Agent在左侧说明需要先上传数据；无计划、无项目版本副作用 |
| UX-02 | 已有数据但未选图时发送“把Y轴改为log10” | Agent要求用户明确选图并提供可见入口；不猜图、不创建计划 |
| UX-03 | 选择图和数据后请求修改标题、Y轴或第二系列 | 确认卡显示具体目标、版本和修改值，不只显示“修改标题/坐标轴/系列样式”等泛化名称；确认前无副作用 |
| UX-04 | 确认并执行编辑 | 同一条状态显示真实当前阶段与呼吸圆点，不显示伪造百分比/剩余时间；完成后成为带Plot ID/版本的结果 |
| UX-05 | 触发NeedsInput、Unsupported或本地拒绝后关闭并重新打开同一项目 | 用户消息和Agent结果仍在对话时间线；项目顶部通知不能是唯一记录 |
| UX-06 | 对标题或其他界面实际标为可撤销的编辑执行按钮撤销、`Ctrl+Z`、`Ctrl+Shift+Z` | 每次撤销/重做都产生新版本；图形回到对应语义状态；原版本未删除 |
| UX-07 | 在聚焦编辑打开“比较上一版本” | 左右两侧显示不同的真实相邻版本号和对应预览；不得把当前预览复制到两侧；v1时按钮不可用 |
| UX-08 | 显式选择多个数据表作为Agent上下文 | 当前工作表和Agent所选数据集可见；最多8个；模型计划不得静默使用未选择数据 |
| UX-09 | 在操作系统减少动态效果设置下运行一次编辑 | 呼吸/位移动画停止，当前阶段文字和可访问状态仍存在 |

当前不验收 `@` 引用、任意历史版本浏览、命名检查点、历史分支、持久化redo栈、任务跳回原消息或独立完成通知；这些能力未实现，不得因界面不存在记本轮产品FAIL，也不得写成PASS。

## 9. 第四阶段：组合、批量与恢复

### 9.1 K25组合图

1. 分别创建两张不同图，例如折线图和柱状图；
2. 每张图完成后加入组合候选，计数从1/4到2/4；
3. 少于两张时，“创建组合图”必须禁用并说明还缺几张；
4. 选择多面板组合图并创建；
5. 成功后必须显示figure ID、固定版本和可打开结果；
6. 打开组合图，确认两个子图的数据、标题和图形身份；
7. 导出PNG/SVG/OPJU；任何失败都必须显示原因，不能静默返回。

### 9.2 批量与部分失败

1. 使用 `batch_compatible_synthetic.xlsx` 创建至少三成员批次；全部成功且各自产生独立结果。
2. 使用 `batch_partial_failure_synthetic.xlsx` 创建包含成功项和失败项的批次。
3. 失败不能撤销已成功项，也不能登记半成品。
4. 用户执行“只恢复失败项”后，只重跑失败项；成功项ID、版本和产物不得改变。
5. 记录每个成员的状态、重试前后ID/版本和最终结果。

### 10.1 PNG与SVG

- 文件非空，可由独立查看器打开；
- 中文标题正常显示，不是方框或缺字；
- 数据几何、轴、系列、图例与桌面预览语义一致；
- SVG仍为可缩放矢量，不以整张位图冒充。

### 10.2 OPJU

从K02、K08、K13、K20、K22、K24、K25、X23、X39中至少各模板家族选择一张代表图导出OPJU。每份必须：

1. 从桌面可见“导出OPJU”入口开始；
2. Origin不可用时在保存对话框前给出可操作诊断；
3. Origin可用时生成非零文件；
4. 使用OriginPro 2024原生窗口打开；
5. 图页和数据表均存在，数据不是嵌入图片；
6. 在Origin中实际修改标题或一个系列样式，保存、完全关闭该项目、重新打开；
7. 修改和数据链接仍存在。

PASS证据至少包括：导出前PlotAgent窗口、Origin图页、Origin数据表、人工编辑后以及保存重开后的截图，并记录OPJU绝对路径、大小和SHA-256。

## 11. 第六阶段：重启恢复

1. 在唯一项目中保留至少两个数据表、一张已编辑图和一个组合图；
2. 记录项目名、数据表显示名、最近plot ID/版本和figure ID/版本；
3. 正常关闭本次PlotAgent及其开发进程；
4. 确认旧窗口退出后，仍从同一 `D:\plotv3`、同一实际HEAD执行 `pnpm dev`；
5. 打开原项目；
6. 对比重启前后的项目、数据身份、最近图和组合图；
7. 最近图必须重新显示，ID/版本不变，不生成重复版本。

聊天瞬态、组合候选篮和未确认计划不作为本轮持久化承诺。

## 12. 已删除图形的黑盒边界

核密度图、Kaplan–Meier生存曲线和森林图已经从正式产品删除。验收包括：

1. 图形库、搜索、Agent可选图形、字段映射、批量和组合入口中均不可发现这些图形；
2. 不能通过别名或自然语言绕过删除后创建近似图；
3. 若另行提供含旧图形引用的历史 `.plotproj` fixture，打开时应显示 `CHART_TYPE_REMOVED`，项目原数据保持不变，不产生新图或OPJU。

若没有提供历史项目fixture，第3项必须记 `UNVERIFIED`；仅凭图形库中搜不到，不能把旧项目迁移墓碑也记为PASS。

## 14. 最终通过条件

本轮只能在以下条件同时满足时判定整体PASS：

1. 环境提交和正式入口已证实；
2. 35/35图均通过正式桌面创建及图形身份检查；
3. 代表图的公开编辑、PNG/SVG和Origin可编辑OPJU全部通过；
4. Agent必测案件在可用模型环境下通过；
5. UX-01至UX-09中适用案件通过，且相邻版本比较使用真实不同版本；
