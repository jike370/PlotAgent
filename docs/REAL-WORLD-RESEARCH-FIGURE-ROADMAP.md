# 真实科研任务驱动的产品升级路线

状态：执行中
起始日期：2026-08-30
适用范围：fig-agent 34 个单图模板、Matplotlib 预览、Origin 原生图与日更复现内容

## 1. 北极星与边界

下一阶段不再只验证“系统是否按既有设计运行”，而要验证：

> 一名科研用户拿到一张真实论文图和对应数据后，能否在合理时间内用 fig-agent 得到语义正确、视觉接近、可继续修改且可交付的科研图。

这不等于把 fig-agent 改成自由画布或通用排版软件。正式范围仍是 34 个单图模板；产品升级的重点是补齐真实任务暴露出的公共编辑能力、上下游契约和双后端一致性。

日更视频与产品升级共用同一案例库，但使用两条队列：

- 内容队列优先选择数据公开、结构清楚、当前能力稳定的图，保证每天可以交付一条复现视频。
- 校准队列保留能暴露真实产品缺口的困难图，用于每周修复和验收，不阻塞当天内容。

## 2. 为什么旧测试不足

此前测试主要证明了四件事：模板可创建、既定动作可执行、状态能够读回、安装包可以运行。这些证据仍然有效，但无法单独证明真实科研任务可完成，原因包括：

1. 测试数据多为围绕既有契约构造的规则样例，类别、缺失值、字段语义和宽长表形态过于整洁。
2. Profile、Agent 知识、编译器和测试常引用同一份能力声明，可能形成“同源自证”。
3. 测试偏重动作是否被接受、期望状态是否写入，较少验证最终画面中真正可见的对象和 fresh-reopen 后的 Origin 原生对象。
4. 测试用例多从模板能力反推任务，缺少从论文图、原始数据和用户语言反推产品能力的独立约束。
5. Matplotlib 与 Origin 各自“成功”并不等于颜色、尺寸、轴线、标签可见性等结果真正对应。

因此，旧测试不是无效，而是证据层级不足。后续必须把真实论文任务变成产品设计与测试的上游。

## 3. 本路线中的“契约”

这里的契约特指上下游对同一能力的声明和实际消费关系。完整链路为：

`模板目录 → Agent 知识/工具 → TaskDraft → 编译器 → 数据规范化 → Matplotlib → Origin → fresh-reopen 验证`

每条公开能力必须同时满足：

1. 上游声明接受的输入，下游必须能够消费；例如 `category` 角色允许数字，就不能在 renderer 前无提示地拒绝数字类别。
2. 下游要求的转换，上游必须有可执行且可发现的动作；不能只在错误文案中建议一个 Agent 无法调用的修复。
3. 修复建议必须指向真实工具、参数和验证路径；不能用自然语言掩盖动作缺失。
4. 双后端声明相同的能力时，必须对可见结果建立同一语义，而不是只比较各自的内部状态。
5. “支持”必须有真实案例证据；只有实现或理论兼容时标为“未验证”，明确做不到时标为“不支持”。
6. 新增能力必须由明确的文献面板提出：至少冻结论文题名、期刊、DOI 或稳定 URL、图号、目标面板、对应原始数据，以及现有产品失败或缺失的证据。只有产品内部设想、截图风格偏好或合成样例时，只能进入候选池，不能立项实现。
7. 文献证据只是立项的必要条件，不是自动纳入条件。每项能力必须同时声明最小支持语义、明确不支持的相邻变体及拒绝理由；没有非目标清单时不得进入实现，不能借一次真实案例把能力边界无限外推。

## 4. 真实案例资产合同

每个案例使用独立目录，并至少保存：

- `README.md`：论文题名、期刊、DOI 或稳定 URL、图号、图类、数据来源、授权/访问方式和复刻范围。
- 论文链接或合法获取的原文；原文不便保存时只保留链接。
- `target_figure.*`：需要复刻的单个面板或清晰裁图。
- 原始数据和 `prepared.*`：整理后的可导入数据；不得覆盖原始文件。
- `prompt.md`：首次绘图和后续改图的自然语言指令。
- `expected.md`：字段绑定、关键视觉语义、允许差异、失败判定、为该案例纳入的最小能力，以及明确不纳入的相邻变体。
- `outputs/`：PNG、SVG、OPJU、fresh-reopen 截图和运行记录。
- 宣发录制不再要求单独维护 `video.md`；复用案例的 `prompt.md`、验收边界和已通过产物即可，已有脚本保留但不作为绿色准入条件。

采用合成数据时必须明确标注“合成”、生成假设与随机种子，不得把它描述为论文原始数据。

### 4.1 用真实论文任务决定新增能力边界（开发强制约束）

本节是横跨现有路线目标的开发约束，用来决定真实论文任务暴露的问题如何归因、能否进入实现以及如何验收；它不新增独立目标、里程碑、待办数量或完成条件。后续目标变更仍须单独决策，不能把“执行本门禁”本身记作一项产品能力或交付成果。

新增能力必须有明确的论文参考或真实任务证据，不能仅凭主观设想加入。论文任务在这里是需求证据与边界裁判，不是要求产品无条件复刻论文中的全部表达。

“论文图不好复现”不能直接等价为“产品缺能力”，也不能给整篇论文只贴一个标签。任何来自真实论文任务的改动在进入 Catalog、Agent 工具、编译器或 renderer 实现前，必须按目标元素逐项核对数据几何、统计变换、视觉编码、标注和版式，并且归入以下五个一级类别之一：

1. **产品能力缺失**：论文数据和方法充分，独立 oracle 能稳定重建目标语义，但 fig-agent 当前公开合同无法表达。只有这一类可以进入新增绘图能力评审。
2. **上下游契约错误**：Agent、TaskIntent、TaskPlan、Catalog、编译器、数据规范化、Matplotlib、Origin 或验证器对同一输入、对象、动作或完成状态的声明互相矛盾。公开合同已有但实际产物、保存、读回或 fresh-reopen 错误也归入此类，按合同或实现 Bug 修复，不新增能力名称。
3. **作者提供的数据不全**：目标元素依赖的原始观测、分组、误差、配对关系、面板映射、过滤/聚合方法或统计参数没有提供，无法建立唯一预期。作者方法缺失是本类的证据子原因，不另设一级类别；不合成隐藏数据冒充原文，也不把未知项计入产品缺口。
4. **图形表达超出产品边界**：目标依赖多面板自由编排、科研图像、任意自由绘制、单篇论文像素级特判或其他不属于当前 34 个结构化表格单图模板的表达。记录拒绝理由并明确不纳入，不因真实论文确有此元素就自动扩张产品。
5. **操作或数据整理问题**：所需信息已经存在，且通过字段选择、筛选、排序、宽长转换、同构拼接、单位换算或其他受控、可追溯的数据处理即可得到目标输入。优先使用数据工作流解决，不把它错误包装成绘图引擎能力；若受控工具本身缺失，另行评审数据能力，不写入视觉动作。

同一面板可以同时存在多类问题，但“混合问题”不是第六个一级类别。必须拆成元素级记录后分别归入上述五类。例如主体几何可以重建、箭头位置没有来源时，主体和箭头分别裁决；不能因为箭头证据不足而否定主体能力，也不能因为主体可画就声称整图完整复刻。

新增能力的充分证据为：`作者数据充分 + 方法参数明确或用户显式给定 + 独立 oracle 可重建 + fig-agent 当前合同失败`。缺少任一项时，默认裁决是“证据不足、暂不判断”，案例保持黄色/红色；Agent 应说明缺失信息、请求参数或建议换用更易复现的文献，不得静默猜测，也不得把未知项计入产品缺口。

数据充分不能只以“附件中有 Excel/CSV”为准，还必须逐项确认：绘图数值、面板/系列/分组映射、单位与类别含义、顺序、误差或配对关系，以及派生量所需输入均可追溯。方法充分必须覆盖会改变几何或科学含义的过滤、聚合、归一化、分箱、误差、拟合和统计检验参数。截图测量、像素取数和拟真合成只能用于诊断或明确标注的演示，不能替代作者证据。

归因结果必须落到元素级清单，而不是给整篇论文只贴一个标签。每个目标面板固定输出：`目标元素`、`作者数据证据`、`作者方法证据`、`独立 oracle`、`当前产品结果`、`归因`、`是否立项`。例如同一箱线图中，箱体统计可能已经支持，原始点叠加可能是产品缺口，显著性字母可能缺少检验输入，复杂分组又可能是另一项未支持能力。只有被单独证明的元素才能推动产品或进入宣传口径。

| 作者数据与方法 | 独立 oracle | fig-agent 当前状态 | 一级归因 | 开发裁决 |
|---|---|---|---|---|
| 完整 | 可稳定重建 | 公开合同无法表达 | 产品能力缺失 | 进入新增能力准入评审 |
| 完整 | 可稳定重建 | 上下游声明矛盾，或合同已有但产物/保存/读回错误 | 上下游契约错误 | 修合同或 Bug，不新增能力 |
| 不完整或存在关键歧义 | 无法建立唯一预期 | 任意 | 作者提供的数据不全 | 待补证据或更换案例，不立项 |
| 完整或不相关 | 可识别目标，但目标超出正式产品范围 | 当前合同明确不承诺 | 图形表达超出产品边界 | 记录理由并明确不纳入 |
| 完整 | 受控整理后可稳定重建 | 绘图合同可以消费整理结果 | 操作或数据整理问题 | 使用或补充数据工作流，不扩张绘图引擎 |
| 部分完整 | 只能重建部分元素 | 部分通过 | 按元素拆分 | 每个元素分别归入上述五类 |
| 完整 | 外部仍不可重建 | 任意 | 暂不能归因 | 补充独立证据，不默认归因产品 |

每个新增能力候选必须在案例台账中登记以下字段，字段不全时不得进入实现：

- 对应论文、稳定 URL/DOI、图号和目标插图；
- 所需原始数据、方法参数及其完整性结论；
- 当前失败所在层：Agent、TaskIntent/TaskPlan、Catalog、编译器、数据处理、Matplotlib、Origin 或验证器；
- 能否抽象为多个模板或多个论文任务共享的稳定科研语义；
- `in_scope`、`out_of_scope`，以及“纳入、暂缓、明确不支持”的裁决与理由；
- Matplotlib 与 Origin 各自的实现路径、可见结果要求、结构 readback 和 fresh-reopen 验收要求。

新增能力进入实现前还必须通过五项准入：有可引用文献证据、有独立预期、对应可复用科研语义、有包含输入/对象/拒绝/读回的机器合同，以及能被声明的后端稳定表达并通过保存后重开验证。默认不纳入：从截图猜测缺失数据或方法、单篇论文像素级特判、为视觉相似篡改数据、把统计检验与图形装饰捆成一个动作、以及没有稳定对象语义或无法 fresh-reopen 验证的自由绘制。

能力评审只允许产生五种明确结果，不能用“以后再支持”掩盖尚未归因：

- **修契约或 Bug**：合同链路声明矛盾，或已有合同在 Agent 规划校验、编译、renderer、保存、读回或验收时失败；修复后用原案例回归，不新建能力名称。
- **新增能力候选**：文献、数据、方法和独立 oracle 闭环，但现有合同确实不能表达；先写最小语义、适用 Profile、后端范围和拒绝矩阵，再决定是否实现。
- **使用或补充受控数据工作流**：通过可追溯整理即可得到现有绘图合同需要的输入；不得为此新增视觉动作。若现有数据工具缺失，只评审最小数据能力。
- **不纳入**：需求只能服务单篇论文的像素特判、依赖猜测或篡改数据、没有稳定原生对象、超出结构化表格绘图边界，或相邻变体没有同一科学语义；记录理由后停止扩张。
- **待补证据**：作者数据、方法、面板映射或第三方复现证据不足；继续检索或更换内容案例，不把未知状态暂记为产品缺口。

每个能力候选还必须登记一个反例：给出与它视觉相似但科学语义不同、因此应被拒绝或走另一动作的任务。没有反例的能力定义通常仍然过宽，不能进入 Agent 公开工具目录。

为避免把责任推错方向，归因时还固定采用以下边界：

- **格式难处理不等于作者数据不全**：数值、分组和方法都存在，只是散落在多 Sheet、宽表、合并表头或结构化字符串中时，先判断能否通过受控整理无损得到目标字段；若能而产品导入/处理合同做不到，归入产品的数据能力缺口。
- **视觉编码通常不依赖作者原始数据**：画布比例、轴线颜色、字号、图例、标签可见性等可从目标图和通用绘图语义建立独立预期；fig-agent 无法表达时属于产品能力或执行缺陷，不能以作者未提供样式表为由归入数据缺口。
- **派生统计必须追溯方法**：均值、误差、箱体、分箱、拟合和显著性既需要输入数据，也需要算法与参数。只有输入或只有图注结论都不足以证明可唯一复现。
- **截图数字化和合成数据是替代路线，不是证据修复**：它们可以制作明确标注的视觉近似内容，但不得把案例升级为“原始数据驱动复现”，也不得反向证明新增能力必要。
- **超出已声明输入范围单独登记**：作者提供的是显微图像、原始仪器信号或需领域专用分析的上游资产，而 fig-agent 当前只承诺结构化表格绘图时，标记为“超出当前产品范围”；既不指责作者数据不全，也不自动扩张为产品缺陷。
- **整图结论采用最弱元素原则，能力结论仍逐元素授予**：任何必要元素未闭环，整张图不能进入完整复刻绿色库存；已经独立通过的元素仍可进入能力回归和宣传中的精确局部口径。

每个候选面板的最小证据包固定包含：目标图或稳定链接、原始附件及哈希、正文/补充方法定位、无损整理记录、独立 oracle 产物、fig-agent 同输入产物，以及逐元素七列表。若缺失项导致无法归因，记录“待补证据”，不使用“产品不支持”作为占位结论。

K03 Nature Communications 2021 Fig. 2a 已作为本门禁的首个实操校验：旧 K03 目录中的同名附件实际来自另一篇论文，先被裁决为“候选证据错配”，没有进入 renderer 归因。重新冻结官方 Source Data 后，A:B 与 E:F 各提供 180 对归一化 X/Y，正文又明确归一化方法；wide-to-long 无损整理、plain Matplotlib oracle 和 K03 产品 v7 预览均通过。真实 Agent 随后正确绑定 `X/Y/group`、生成两组实心/空心语义、双轴、图例和画布动作，经确认执行到 `completed_verified`；首版外部评分脚本却因要求冗余 `marker_shape=circle`、混淆计划别名与原生对象等原因给出假阴性，属于评估契约缺陷，不是 Agent 失败。首个 Agent OPJU fresh-reopen 又暴露 Origin 官方散点模板把组间标记自动递增为方形/圆形、空心填充未得到白色可见语义；该后端缺陷已修复，`build/real-world-k03-fig2a-agent-origin-fixed-20260830-r3/` 读回 1 个图页、1 个工作簿、2 个原生圆形散点序列和四列各 180 行，实心/空心语义正确，OPJU SHA-256 为 `C8B61A5150CF3F5103B67A767891F437469E034F21C03EBC71DC6E4482E230B2`。COM fresh PNG 随后出现文本横线，但对象枚举、完整 Format Tree、默认模板和新建文本对照均证明它不属于 OPJU 持久化属性；OriginLab 的同版本公开案例确认这是 OriginPro 2024 SR1 的 OLE/嵌入渲染缺陷。退出 COM 后由独立 `Origin64.exe` 打开同一 OPJU 导出的 PNG 无横线，因此 RW-041 改判为验证环境假阴性，K03 升级为绿色库存。结构读回与独立进程可见导出从此是两个门禁，不能再用 COM 截图替代最终视觉证据。K03 不公开 marker 精确描边宽度；作者未给该参数且它不改变面板科学语义，明确不纳入。

## 5. 案例分级与日更选择

### 5.1 分级

- 绿色：数据已获取并可直接整理；模板已稳定；不依赖已知缺口；2 小时内可完成复刻和录制。
- 黄色：需要中等数据整理，或存在可绕开的视觉差异；可以进入内容库存，但必须预演。
- 红色：依赖未实现能力、Origin fresh-reopen 失败、字段语义不明确或数据来源不可核验；只进入校准队列。

分级维度包括数据可得性、清洗成本、模板稳定性、视觉编辑数量、Origin 风险和视频叙事价值。任何红项都不能因日更压力被包装成“已支持”。

### 5.2 日更机制

- 常备 7–14 个已经预演的绿色案例，发布当天不临时选题。
- 单条视频目标 60–180 秒；从数据整理到成片控制在 2–3 小时。
- 标准结构：参考图与研究问题 → 数据结构 → 一句话任务 → Agent 规划/确认 → 结果与关键改图 → PNG/SVG/OPJU 交付。
- 预演 30–45 分钟仍无法稳定完成时，立即换用库存案例，原案例转入校准队列。
- 日更先使用线图、散点、普通/成组/堆叠柱、箱线、直方、面积和热图等稳定类型；X35、X36、X40 在当前问题关闭前不作为当天保底案例。

内容选择允许向“易复现但具有清晰科研叙事”的参考图让步。日更目标是持续展示真实可完成任务，不是每天挑战能力上限。

## 6. 产品升级优先级

### P0：契约与交付正确性

## 7. 公共画布动作的目标合同

公共能力采用独立 `set_canvas` 动作，而不是把 `canvas_aspect_ratio` 塞进某个图类的私有参数：

- 可表达 `width_mm`、`height_mm`，或只给 `aspect_ratio` 后按默认高度计算。
- Matplotlib 修改 figure page size；Origin 修改 graph page size。
- 修改前后都保留图类自身结构和数据语义。
- S34 等要求等比例数据坐标的图，页面可变，但绘图区仍须保持其 profile 不变量。
- 必须读回实际宽高，并在 Origin fresh-reopen 后再次验证。
- `set_canvas` 只承诺页面物理尺寸，不隐式猜测字号、图例和边距；真实任务若要求元素随页面重排，必须由可读回的显式版式动作或动作组合完成。
- Profile 只声明例外或范围限制；适用的大多数图默认获得这一公共能力。

### 7.1 下一项公共设计：产品排版基线

K08 的 75×100 mm 实例证明“页面尺寸正确”不等于“交付可读”。下一项公共设计不是给 K08 写字号特例，而是引入可审计的产品排版基线：

- 初始图在两个后端使用同一组物理单位默认值：图标题、轴标题、刻度、图例字号及线宽均以 pt 表达。
- 默认值由公共主题与可见信息密度共同解析；Profile 只能声明必要例外，不能各自继承不可比较的 Origin 模板默认值。
- 显式 `set_axis`、`set_title`、`set_legend` 等用户动作始终覆盖基线；重新设置画布不能覆盖用户已经明确指定的样式。
- 当类别数量、旋转角度和页面尺寸组合会造成必然重叠时，系统应返回可执行的排版建议或显式 `fit_layout` 计划，不静默缩成不可读文字。
- Matplotlib 检查最终 Text/Spine/Legend artist；Origin 必须保存、关闭、fresh-reopen 后读回实际 pt、页面尺寸和对象边界。
- 该基线属于 renderer 解析结果，不伪装成用户主动提出的动作；诊断与 readback 必须能说明哪些值来自产品默认、哪些来自显式编辑。

已完成 v1 的确定性切片：公共默认固定为图标题 10 pt、轴标题 9 pt、刻度 8 pt、图例 8 pt；Matplotlib 在 backend `rc_context` 中解析，Origin 在 T1 后处理写入并 fresh-read，显式动作按属性覆盖。该切片只关闭“两个后端继承不同默认字号”，尚未关闭类别密度、旋转、边距与碰撞诊断，也未替代 K08 真实 OPJU 复验。

- K04 的 `2.6` 与 K08 的 `16.5` 已在 OriginPro 2024 SR1 保存、关闭、另一进程 fresh-reopen 后精确读回；自动门禁 36/36 通过，证据位于 `build/release-matrix/reference-line-native-k04-k08-20260830/`。

### 7.3 下一项公共设计：语义 Callout，而不是通用坐标箭头

K04 和 K08 Fig. 4 的剩余共同能力不是“再放一段文字”，而是把文字与科研语义对象建立可读、可编辑的指向关系。现有 `add_annotation` 只在首个 Matplotlib/Origin layer 上放置文字，而且当前没有任何 Profile 把它声明为公共能力；在双 Y、多层和分面图中也没有目标轴对合同。因此不能直接给旧动作追加箭头参数。

对官方 `K08_Column/source_data/Source Data/Fig4.xlsx` 的只读审计进一步修正了设计：Fig. 4b/4d 各只有 8 个国家类别和柱值，均值分别是 `16.26640875` 和 `0.70573625`，工作簿没有箭头坐标或“被指向的数据点”。目标图中的箭头实际在解释均值参考线，而不是标记某根柱。这意味着第一版不应把它伪装成 series/datum callout。可复核的源表摘要位于 `build/real-world-k08-fig4-callout-audit-20260830/source-audit.json`。

- 第一切片定义独立、可寻址的 `callout_id`，目标仅允许已存在的 `reference_line_id`；参考线提供科学含义和精确 Y 值，callout 只声明沿线的相对位置、文字位置和箭头样式。
- 沿线位置使用 `0..1` 的轴内比例，不暴露“第 3.5 个类别”这类后端私有坐标；文字位置明确使用 axes fraction。两种坐标字段分名，禁止把 data 与 axes 数值混在同一个 `x/y` 中。
- 线型、颜色、pt 线宽、箭头头型、可选文字和文字样式采用闭集参数；同一 `callout_id` 的后续动作覆盖旧状态。
- Matplotlib 使用原生 Annotation/ArrowPatch；Origin 使用可保存的原生箭头与文字对象。两端都要在最终对象和 fresh-reopen 后读回目标参考线、相对锚点、文字位置、可见性与样式。
- 首个门禁选 K08 Fig. 4b/4d 的“均值参考线说明”，其后才分别设计 datum-bound 与 free-coordinate 变体；双 Y 变体必须显式目标语义 series 或轴，不能默认落到左轴。矩阵、3D 和 Trellis 在作用域合同明确前不公开。
- K04 的混合标记已在后续独立切片关闭；完整案例仍须设计并验证真实数据坐标注释语义，不能用 reference-line-bound callout 冒充。
- 日更策略不等待该能力：优先录制无需箭头、混合标记和复杂分面的 K15/K13/K10/K18 候选，避免把能力建设进度变成日更断供点。

### 7.4 已完成受控数据操作：结构化映射标量提取

K04 官方 `source_data.xlsx > Fig. 4` 的 `sigma` 不是普通数字列，而是 Python 风格映射字面量。475 行同时含 `value` 与 `confidence_level`，最后 9 行只含 `value`；目标图恰好把这 9 行画成三角形。因此不能用“取第一个数字”的正则临时清洗，也不能只提取 `value` 后静默丢弃置信来源。

- 新增封闭操作 `extract_mapping_fields`，输入为一个已检查的 text 字段；每个输出显式声明精确键、输出别名、显示名、目标标量类型和是否必需。
- 解析仅使用有长度上限的字面量 AST；根节点必须是字典，键必须是唯一字符串，值只能是有限数值、文本、布尔或空值。未知键、重复键、嵌套结构、代码表达式和隐式字符串转数字全部稳定失败。
- 可选键缺失保留为 `None`，并可同时声明独立布尔存在性输出：键存在得到 `true`、合法映射省略该键得到 `false`、整个源单元格缺失仍为缺失。原始结构列不被覆盖；编译器、执行器和 `binding_evidence` 共享 `sigma_value → sigma` 的同一字段血缘。
- 真实源表 484 行门禁全部通过：数值 484、置信标签 475、显式缺失 9、存在性输出 475 个 `true` 与 9 个 `false`、不同置信标签 86，数值范围 `1e-15..0.008212832236281`。证据位于 `build/real-world-k04-structured-extraction-20260830/run-metadata.json`。
- 本操作只陈述映射键是否存在，不把“缺失 confidence”自动解释成三角形。该科研语义由下一个独立、显式的逐点视觉编码动作承担。

### 7.5 已完成 K04 逐点形状映射

K04 目标图要求同一个颜色映射气泡系列中的 475 个点显示为圆形，缺少 `confidence_level` 键的 9 个点显示为向下三角形。不能通过拆成两个伪系列、覆盖统一 marker 或在 renderer 中硬编码“缺失即三角形”实现，否则会破坏尺寸/颜色映射、系列身份和 Agent 可审计性。

- 额度以总额度而不是当前余额为基准：本目标启动时总额度余额为 67%，最多再使用 42 个百分点，必须在总额度剩余 25% 时停止并把余量留给秋招准备。
- 在契约和受影响范围稳定前，只跑定向测试；不提前重复全量 34×多后端矩阵。
- 优先使用本地已有论文、图片和数据；凡需访问机构论文资源，先启动 EasyConnect，再复用已经登录的机构会话。
- 校园 VPN 只用于合法访问和下载，不绕过授权、DRM 或站点限制。
- 每轮只推进能形成证据闭环的最小切片：真实案例 → 失败 → 契约 → 实现 → 双后端验证 → 内容复用。
- 不从功能名称反推需求。每个新增能力都必须在案例台账中引用明确文献与图号，并保留目标面板和原始数据；若后续发现图类或数据语义错配，立即撤回能力立项而不是修改案例来迎合实现。
- 每条新增能力记录必须成对维护 `in_scope` 与 `out_of_scope`。非目标不是“以后再说”的模糊待办，而是当前产品边界；只有新的明确文献、数据和失败证据证明其具有复用价值时才重新评估。
