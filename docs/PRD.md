# fig-agent 产品需求文档（内部工程：PlotAgent v3）

> 本文与 [产品决策](./PRODUCT-DECISIONS.md)、[编排架构](./AGENT-ORCHESTRATION-ARCHITECTURE.md)、[Agent Native 绘图引擎](./AGENT-NATIVE-PLOTTING-ENGINE.md) 和 [T1 视觉矩阵](./ORIGIN-VISUAL-CAPABILITY-MATRIX.md) 共同构成当前产品基线。

## 1. 问题与目标

科研用户通常需要在数据整理、字段理解、图类选择、细节调整和 Origin 后续编辑之间反复切换。fig-agent 允许用户直接导入原始表格数据，用自然语言说明单图或批量任务，并继续提出改图要求。产品不替用户解释科研结论，而是把明确的绘图目标转换为可以核对、可以恢复的任务，最终交付 PNG、SVG 或 Origin 原生可编辑的 OPJU。

成功标准：

- 用户不需要先整理成 fig-agent 的固定表格模板，就能在一个项目中导入真实数据、选择图类、确认字段和参数并得到图；
- 程序先完成廉价结构解析；自然语言目标由 Agent 理解，简单目标一轮完成、复杂目标按需调用工具；
- 单图、同类批量、异构批量和受支持的多来源同图任务可以逐项确认、局部失败和局部恢复；
- 用户可以继续通过自然语言修改受支持的标题、坐标轴、系列、图例和样式，修改结果形成可追溯的图形版本；
- PNG/SVG 与 OPJU 的数据、字段和视觉语义一致；
- OPJU 在已验证的 OriginPro 2024 SR1 中重开后仍保留原生工作表、图形对象和可编辑数据绑定。

## 2. 用户流程

### 2.1 单图

1. 用户创建/打开项目并导入数据。
2. 用户选择一个正式图类。
3. 用户可直接在确认卡映射字段，或输入自然语言目标。
4. Pi 根据用户原文和结构化上下文提出字段绑定；必要时查看数据或预演数据操作并提交 TaskIntent。
5. 确认卡展示数据样本、字段角色、图类和视觉改动。
6. 用户确认后，TaskPlan 调用本地绘图引擎并创建 PlotDocument 版本。
7. 用户继续用自然语言或聚焦编辑控件修改 T1 视觉参数，可撤销/重做。
8. 用户导出 PNG、SVG 或原生可编辑 OPJU。

### 2.2 批量与多来源

- 用户可以一次选择 2–8 个数据表，并用自然语言明确“数据 A 画 A 图、数据 B 画 B 图”或“每份数据各画同一种图”。
- 每个 TaskItem 独立保存来源、图类、字段、视觉动作、状态和输出。
- 支持的单图 Profile 可将多份完全同构数据纵向拼接，并增加来源分组字段绘在同一图中。
- 不做模糊 join、隐式聚合或多面板组合；单位换算必须由 Agent 明确规划、程序验证并在确认后执行。

### 2.3 流程复用边界

正式桌面当前不公开 WorkflowRecipe 保存、匹配或重放。代码中的 Recipe 合同和服务不是用户能力，也不得被黑盒说明成已实现入口。未来若重新开放，只能由用户显式保存、显式选择、重新校验并再次确认；不得静默学习或自动套用历史流程。

## 3. 输入

- Excel：`.xlsx/.xls/.xlsm`，多 sheet 独立呈现；不执行宏、VBA、公式或外链刷新。
- 文本：`.csv/.tsv/.txt/.dat`，识别分隔符、编码、表头和仪器前导/尾部元数据。
- 多文件导入串行登记，保留文件名、工作表/数据块名、字段单位和来源坐标。
- 输入不要求符合 fig-agent 专用模板。程序先识别二维数据区域、字段、类型和单位候选，再将必要的整理动作放入确认计划；原始文件保持只读。
- 歧义解析只提出完成导入所需的最小问题；不能静默猜测。
- 当前输入范围是数值表格数据，不包括科研图像、数据库或实时仪器流。

## 4. 图类范围

公开目录固定为 34 张单图，逐图 Origin 官方路线见 [官方模板映射](./ORIGIN-OFFICIAL-TEMPLATE-MAPPING.md)。每个 Profile 声明：

- 必填/可选/可重复字段角色；
- 稳定图形对象别名；
- Matplotlib 与 Origin 共同支持的动作；
- 数据结构、固定计算和动态变化门禁；
- Origin 官方模板/菜单/X-Function、原生对象读回和 fresh-reopen 资格。

产品不提供组合图或隐藏的兼容入口。

## 5. Agent 与编排

所有自然语言请求原样进入 Pi。前端和 Core 不从文本中猜数据源、图类、字段、批量关系、数据操作、重试目标或视觉参数。Pi 先尝试一轮直接生成 TaskIntent；需要事实时调用有界数据检查工具；信息不足时结构化追问；验证失败时在预算内修订。

Pi 仍负责从自然语言解析图类，但每个 `task_kind=create` 项必须在 `profile_selections` 中携带且仅携带一条同 `item_id`、同 `profile_id` 的图类来源。未被用户覆盖的 UI 预选使用 `basis=ui_selected`；自然语言指定使用 `basis=user_instruction`，并附带用户原话中的最短图类证据。Core 只校验 UI 来源、原文证据和目录 Profile 的一致性，不自行做关键词路由。缺少结构化来源是 Agent 输出合同错误，由 Pi 在同一 activation 内返修；使用“一张图”等泛化文字、伪造引用或引用与 Profile 不符时同样拒绝该草稿，只有真实语义歧义才由 Agent 提交结构化图类追问。

Pi 的职责是任务拆解、数据指代理解、字段绑定、受控数据处理规划、单位目标选择、失败修复策略和自然语言视觉参数翻译。Core 的职责是安全别名、版本/权限/能力/量纲/科研规则校验、工具执行、TaskPlan 编译、确认、事务执行和恢复。

程序可以零模型执行的只有用户直接操作结构化 UI。数据导入前的廉价程序处理只识别文件结构、类型、单位候选和来源，不理解用户目标。

## 6. T1 视觉能力

自然语言和前端控件必须覆盖同一组 T1 参数：

- 线：颜色、宽度、实线/虚线/点线/点划线/不显示；
- 符号：形状、大小、填充色、边缘色、透明度、实心/空心；Origin 符号边缘宽度保留官方模板默认值，不作为公共编辑参数；
- 填充：填充色、边框色、边框宽度、透明度；
- 文字：字体、字号、粗细、颜色、旋转；
- 坐标：标题、范围、linear/log10/datetime/categorical、反向、刻度和网格；Origin 的标准单层笛卡尔图使用四侧轴线作为产品默认值，上、右仅作为干净外框，不显示主/次刻度线或刻度值。矩阵/色图、原生 Trellis、中央轴和重叠双轴模板保留官方轴框拓扑，真正承担数值语义的右轴继续显示官方刻度与刻度值；Matplotlib 默认态独立。用户显式设置轴线可见性时，两种后端均以该设置为权威；
- 图例：显示、位置、列数、字体、字号、边框；
- 连续色板：色板、反转、最小/最大和中点；
- 不确定性：误差棒颜色/宽度/端帽，误差带填充/边缘/透明度；
- 数据标签：显示、字段、字体、字号、颜色、旋转和偏移。

离散选择与连续数值都必须在确认前可核对；任何后端不支持的参数不进入该 Profile 的能力表。
每个公开系列身份都必须能被独立编辑。Origin 官方模板若用分组递增样式控制多个原生绘图对象，执行公开系列编辑时只解除该图层的表现分组，再按系列写入样式；不得保留会覆盖用户设置的组样式，也不得因此破坏原生数据绑定、图对象或可编辑性。

逐点视觉编码只有在 Profile 明确公开时才能进入 TaskIntent。`set_point_marker_map` 必须指定目标系列、一个布尔/文本/类别字段，以及对实际观察值穷尽且无冗余的值—形状映射；未映射值和数据中未出现的声明值都稳定失败。统一 `set_series_style.marker_shape` 与逐点映射按动作顺序互相覆盖，重新绑定数据后旧逐点映射失效。当前该能力只向 K04 公开，并在同一散点对象上保留连续尺寸和颜色映射。

箱线图原始观测叠加只有在 Profile 明确公开时才能进入 TaskIntent。`set_observation_overlay` 不接受字段或第二数据集，只使用计算当前 K13 箱体的同一批 value 行；支持确定性横向位置、符号、大小、填充、描边、透明度和显示状态。它不改变中位数、四分位数或须线，不等同于 beeswarm、violin、配对轨迹、显著性标注、二级类别轴或预计算箱线统计。当前该能力只向 K13 公开，并要求 Matplotlib 与 Origin 保存后仍能分别读回箱体和原始点对象。

## 7. 数据处理

TaskIntent 仅允许封闭数据操作：选择/重命名字段、行筛选、多键排序、显式排除已检查行、删除已证实空字段、严格类型转换、结构化映射标量提取、登记算子的派生字段、单位声明/换算、数值分箱、宽转长、长转宽、同构来源拼接和共享 X 严格对齐。Agent 可先调用受限检查工具理解输入，再把规范化操作写入 TaskIntent；Core 使用同一确定性实现校验、预演和执行。结构化映射提取要求全部键和类型显式声明，不执行代码、不接受嵌套值、不隐式转换或丢弃未知键；重复键不隐式聚合。可选键可以同时声明独立布尔存在性输出：合法映射缺少该键得到 `false`，键存在（包括显式空值）得到 `true`，整个源单元格缺失仍保留为缺失。筛选为空、结构不同、量纲不兼容或结果缺少绑定字段时稳定失败，原始数据和导入元数据保持不变。

图类不可分割的固定计算必须由 Profile 自动声明或由真实计算工具执行；不能存在 Schema 可提交但执行器不执行的名义动作。

## 8. 任务、版本与恢复

- 用户确认前不创建图、不修改版本、不导出文件。
- 每个非导出动作创建一个线性 PlotDocument 版本并记录 action ID。
- 批量成功项立即保留；失败项记录稳定错误并可单独继续。
- 项目重启后恢复项目、数据身份、最近图和 TaskPlan 状态；已成功 TaskItem 不重复执行。
- 当前项目 schema 为 v7；本机 v5/v6 工作区只执行代码已覆盖的事务性增量迁移，其他版本稳定拒绝且不改写原文件。

## 9. 输出

- PNG/SVG 由 Matplotlib backend 导出；SVG 保持安全矢量内容。
- OPJU 由 Origin backend 使用官方原生路线生成，保存实际使用数据、worksheet designation、graph/layer/plot、轴、图例和 Profile 声明的数据标签。
- 自然语言修改和结构化界面修改进入同一 PlotDocument 版本；用户再次导出 OPJU 时，受支持的改动必须写入对应的 Origin 原生对象。产品不反向导入或直接修改任意现有 OPJU。
- OPJU 构建与验证使用独立受控 Origin 会话；fresh reopen 读回通过后才原子发布。
- 导出后 UI 必须显示明确成功记录、文件类型、目标图、大小和哈希。

### 9.1 Origin 兼容与安装条件

- 当前程序只接受文件版本为 `10.1.0` 的 Origin 2024。
- OriginPro 2024 SR1（`10.1.0.178`）是当前完成完整 OPJU 矩阵验证的版本。
- OriginPro 2024 SR0 和标准版 Origin 2024 允许进入环境预检与导出链路，但在完成同等范围验证前不能写成“已经完整支持”。
- Origin 2024b、2025、2025b、2026 和其他文件版本稳定拒绝，并显示检测到的真实版本。
- 用户可以手动选择 `Origin64.exe` 等 Origin 主程序；配置持久化并同时用于检测和实际导出。
- 安装包自带 fig-agent 所需的 Python 运行环境和 Origin 连接组件，不要求用户另行配置 Python。PNG/SVG 导出不依赖 Origin；OPJU 需要本机安装并授权可用的受支持 Origin。

## 10. 交互与可访问性

- 交互以对话推进，但图类选择和最终确认由用户掌握。
- 对话使用持久化有序时间线：用户消息、Agent 回复、计划、图形版本和导出结果均按发生顺序追加；同一计划只原位更新状态，执行结果必须位于该计划之后。
- 图形目标使用项目内稳定、单调递增且不复用的 `@图N`；显式提及可选择一个或多个图并解析到各自最新版本，模糊自然语言不得被前端或程序偷偷绑定到当前图。
- 同一项目一次只接受一个前台 Agent 任务；项目之间保持独立，受控 Origin 会话按底层资源约束串行。
- 任务阶段使用可见、真实、非伪造的实时反馈。
- 确认卡的只读数据预览与决策区视觉分离，字段角色贴近原始列名。
- 键盘可完成字段选择、确认、取消、撤销/重做；焦点、状态和错误使用语义化可访问属性。

## 11. 非功能要求

- Windows Electron，单主窗口；renderer sandbox、context isolation、无 Node integration。
- 用户可见产品名、安装包、官网和对外文档统一使用 `fig-agent`；内部包、协议和存储标识继续使用 `plotagent`，不得为品牌调整破坏项目兼容。
- 当前公开测试基线为 Windows 11 x64；版本和兼容范围必须在下载页与应用内保持一致。
- Python Core 是项目 SQLite 唯一写入器；大型数据只传对象引用。
- 结构化 UI 可以零模型调用；自然语言任务记录轮次、工具调用、延迟与成本。
- 项目、图形版本和导出结果保存在本机；自然语言任务会把用户指令、字段元数据和受控样本发送到用户选择的模型服务，API Key 只保存在 Windows Credential Manager。
- 远程模型失败不影响手动绘图和本地导出。

## 12. 发布验收

- 新架构源码、Schema、RPC、持久化和测试中不存在第二套计划或上下文合同。
- 34 图现有 default/edited/dynamic/fresh 资格不因 T1 扩展回退。
- 每项 T1 参数至少由一个前端控件用例、一个自然语言 TaskIntent 用例和双 backend readback 用例证明。
- instruction 原样传递、Agent 数据工具、结构化追问、TaskCompiler、部分失败恢复和 Agent Foundation 统一评测全部通过。
- 最终探索性黑盒仅接收用户可见功能说明，由独立会话设计测试，本窗口在正式 Windows Electron UI 执行并保留证据。
