# PlotAgent v3 产品需求文档

> 本文与 [产品决策](./PRODUCT-DECISIONS.md)、[编排架构](./AGENT-ORCHESTRATION-ARCHITECTURE.md)、[Agent Native 绘图引擎](./AGENT-NATIVE-PLOTTING-ENGINE.md) 和 [T1 视觉矩阵](./ORIGIN-VISUAL-CAPABILITY-MATRIX.md) 共同构成当前产品基线。

## 1. 问题与目标

科研用户通常需要在数据清理、字段理解、图类选择、细节调整和 Origin 后续编辑之间反复切换。PlotAgent 的目标不是替用户解释科研结论，而是让用户用自然语言和可见控件可靠完成绘图任务，并交付可复现、可追溯、可编辑的结果。

成功标准：

- 用户能在一个项目中导入真实数据、选择图类、确认字段和参数并得到图；
- 程序先完成廉价结构解析；自然语言目标由 Agent 理解，简单目标一轮完成、复杂目标按需调用工具；
- 批量任务可逐项确认、局部失败和局部恢复；
- PNG/SVG 与 OPJU 的数据、字段和视觉语义一致；
- OPJU 在 OriginPro 2024 中重开后仍可编辑。

## 2. 用户流程

### 2.1 单图

1. 用户创建/打开项目并导入数据。
2. 用户选择一个正式图类。
3. 用户可直接在确认卡映射字段，或输入自然语言目标。
4. Pi 根据用户原文和结构化上下文提出字段绑定；必要时查看数据或预演数据操作并提交 TaskDraft。
5. 确认卡展示数据样本、字段角色、图类和视觉改动。
6. 用户确认后，TaskPlan 调用本地绘图引擎并创建 PlotDocument 版本。
7. 用户继续用自然语言或聚焦编辑控件修改 T1 视觉参数，可撤销/重做。
8. 用户导出 PNG、SVG 或原生可编辑 OPJU。

### 2.2 批量与多来源

- 用户可以一次选择 2–8 个数据表，并用自然语言明确“数据 A 画 A 图、数据 B 画 B 图”或“每份数据各画同一种图”。
- 多文件分别执行通用解析/DataPreparationRecipe/Agent 辅助整理；每个文件可以输出多个独立 sheet/block SourceDataset，单文件失败不回滚其他成功来源。
- 每个 TaskItem 独立保存来源、图类、字段、视觉动作、状态和输出。
- 支持的单图 Profile 可将多份完全同构数据纵向拼接，并增加来源分组字段绘在同一图中。
- 不做模糊 join、隐式聚合或多面板组合；单位换算必须由 Agent 明确规划、程序验证并在确认后执行。

### 2.3 数据整理复用

原始文件成功整理为规则数据表后，界面可以提示用户是否固化本次数据整理流程。用户确认后只保存来源结构匹配条件、定位/解析/拆块/必要转置等机械步骤及输出保证，不保存后续字段选择、单位换算、FieldMapping、图类和视觉动作。

上传、发现新 sheet/block、替换来源或重新整理时，程序自动发起匹配：先按文件/结构硬条件筛选，再按仪器标记、表头、单位位置和布局特异性排序，对候选做有界沙箱试运行并校验输出。唯一合格候选自动应用；多个同级候选由用户选择；全部失败时由 Agent 接手。匹配不使用自然语言相似度。

Recipe 输出规则 SourceDataset：行列边界、字段/行 ID、类型、单位候选、缺失/解析失败状态、仪器元数据和来源坐标明确；一个 sheet/block 默认形成一个表，原始顺序与原文件不变。规则表不等于 renderer-ready 数据。用户选图后，程序只做 Profile 机械兼容性检查，Agent 决定字段语义与必要 DataOperation。

Agent/用户完成非平凡整理后，程序从实际成功的机械 trace 生成严格 Recipe 候选；规则表预览经用户确认正确后即可保存，不等待绘图或导出。Recipe 默认进入个人库，项目固定不可变版本。更多样本成功只增加证据；扩大匹配范围或修改步骤必须显式生成新版本。执行失败稳定回退 Agent，连续结构性失败后停止自动应用并提示检查。

Recipe 以单个上传文件为执行单位，可以从 workbook 或仪器文件输出多张独立规则表。跨文件、跨 sheet/block 的对应、批量拆分和同图多来源不进入 Recipe；Agent 根据用户目标提出，程序验证同构性和单位后进入确认。

## 3. 输入

- Excel：`.xlsx/.xls/.xlsm`，多 sheet 独立呈现；不执行宏、公式或外链刷新。
- 文本：`.csv/.tsv/.txt/.dat`，识别分隔符、编码、表头和仪器前导/尾部元数据。
- 多文件导入串行登记，保留文件名、工作表/数据块名、字段单位和来源坐标。
- 歧义解析只提出完成导入所需的最小问题；不能静默猜测。

## 4. 图类范围

公开目录固定为 34 张单图，逐图 Origin 官方路线见 [官方模板映射](./ORIGIN-OFFICIAL-TEMPLATE-MAPPING.md)。每个 Profile 声明：

- 必填/可选/可重复字段角色；
- 稳定图形对象别名；
- Matplotlib 与 Origin 共同支持的动作；
- 数据结构、固定计算和动态变化门禁；
- Origin 官方模板/菜单/X-Function、原生对象读回和 fresh-reopen 资格。

产品不提供组合图或隐藏的兼容入口。

## 5. Agent 与编排

所有自然语言请求原样进入 Pi。前端和 Core 不从文本中猜数据源、图类、字段、批量关系、数据操作、重试目标或视觉参数。Pi 先尝试一轮直接生成 TaskDraft；需要事实时调用有界数据检查/预演工具；信息不足时结构化追问；验证失败时在预算内修订。

Pi 的职责是任务拆解、数据指代理解、字段绑定、受控数据处理规划、单位目标选择、失败修复策略和自然语言视觉参数翻译。Core 的职责是安全别名、版本/权限/能力/量纲/科研规则校验、工具执行、TaskPlan 编译、确认、事务执行和恢复。

程序可以零模型执行的只有：用户直接操作结构化 UI，或唯一匹配且沙箱校验通过的 DataPreparationRecipe。Recipe 只替代原始文件整理阶段；后续自然语言任务仍由 Agent 理解。无 Recipe 时的廉价程序处理只识别文件结构、类型、单位候选和来源，不理解用户目标。

Agent 默认获得任务相关来源的schema、单位、质量摘要、前 5 行、Recipe摘要和Profile机械兼容结果；批量中的其他来源只提供目录摘要。需要时可通过有界工具查看更多规则表数据、确定性样本、原始文本/Excel区域和仪器元数据。小表可在预算内读完，大表按范围读取；超预算时追问或停止。所有读取可审计，远程模型只接收已授权且实际请求的数据片段。

## 6. T1 视觉能力

自然语言和前端控件必须覆盖同一组 T1 参数：

- 线：颜色、宽度、实线/虚线/点线/点划线/不显示；
- 符号：形状、大小、填充色、边缘色、边缘宽度、透明度、实心/空心；
- 填充：填充色、边框色、边框宽度、透明度；
- 文字：字体、字号、粗细、颜色、旋转；
- 坐标：标题、范围、linear/log10/datetime/categorical、反向、刻度和网格；
- 图例：显示、位置、列数、字体、字号、边框；
- 连续色板：色板、反转、最小/最大和中点；
- 不确定性：误差棒颜色/宽度/端帽，误差带填充/边缘/透明度；
- 数据标签：显示、字段、字体、字号、颜色、旋转和偏移。

离散选择与连续数值都必须在确认前可核对；任何后端不支持的参数不进入该 Profile 的能力表。

## 7. 数据处理

TaskDraft 仅允许封闭数据操作：选择/重命名字段、行筛选、多键排序、登记算子的派生字段、单位换算、宽转长、长转宽和同构来源拼接。Agent 可先调用同实现的预演工具查看输出 schema、样本和影响，再写入 TaskDraft。重复键不隐式聚合；筛选为空、结构不同、量纲不兼容或结果缺少绑定字段时稳定失败。原始数据和导入元数据保持不变。

Agent 在预算内可以自行预演登记操作，预演不产生项目副作用。字段选择/显示名、量纲明确的单位换算、无损 reshape、稳定排序和同构纵向拼接可以与绘图决策集中确认；行筛选必须突出显示条件与排除行数。去重、隐式聚合、缺失值填补、异常值删除、任意 join、平滑、标准化、拟合、自由公式和任意代码当前不提供。所有确认后的操作生成新的 PreparedDataView，不覆盖规则 SourceDataset。

图类不可分割的固定计算必须由 Profile 自动声明或由真实计算工具执行；不能存在 Schema 可提交但执行器不执行的名义动作。

## 8. 任务、版本与恢复

- 用户确认前不创建图、不修改版本、不导出文件。
- 每个非导出动作创建一个线性 PlotDocument 版本并记录 action ID。
- 批量成功项立即保留；失败项记录稳定错误并可单独继续。
- 项目重启后恢复项目、数据身份、最近图和 TaskPlan 状态；已成功 TaskItem 不重复执行。
- 旧项目 schema 不自动迁移或兼容打开。

## 9. 输出

- PNG/SVG 由 Matplotlib backend 导出；SVG 保持安全矢量内容。
- OPJU 由 Origin backend 使用官方原生路线生成，保存实际使用数据、worksheet designation、graph/layer/plot、轴、图例和标注。
- OPJU 构建与验证使用独立受控 Origin 会话；fresh reopen 读回通过后才原子发布。
- 导出后 UI 必须显示明确成功记录、文件类型、目标图、大小和哈希。

## 10. 交互与可访问性

- 交互以对话推进，但图类选择和最终确认由用户掌握。
- 任务阶段使用可见、真实、非伪造的实时反馈。
- 确认卡的只读数据预览与决策区视觉分离，字段角色贴近原始列名。
- 键盘可完成字段选择、确认、取消、撤销/重做；焦点、状态和错误使用语义化可访问属性。
- 通用解析或唯一 Recipe 成功后直接显示“已整理”摘要及查看/重新整理入口；多个同级 Recipe 在调用 Agent 前展示候选选择卡。
- Agent 辅助整理且已有绘图目标时，原始片段、整理后预览、机械步骤、输出表、字段绑定、图类和视觉参数合并为一次最终确认；仅上传时使用独立整理确认卡。
- 批量整理按文件显示成功/失败并只重试失败项。重新整理创建新 SourceDataset 版本；有下游引用的历史版本保留且可追溯。

## 11. 非功能要求

- Windows Electron，单主窗口；renderer sandbox、context isolation、无 Node integration。
- Python Core 是项目 SQLite 唯一写入器；大型数据只传对象引用。
- 结构化 UI 和通过唯一结构匹配复用 DataPreparationRecipe 的数据整理可以零模型调用；自然语言任务记录轮次、工具调用、延迟与成本。
- 数据披露默认最小化，支持用户查看本次 Agent 读取清单；数据内容、列名和仪器说明均按不可信输入处理。
- 远程模型失败不影响手动绘图和本地导出。

## 12. 发布验收

- 新架构源码、Schema、RPC、持久化和测试中不存在第二套计划或上下文合同。
- 34 图现有 default/edited/dynamic/fresh 资格不因 T1 扩展回退。
- 每项 T1 参数至少由一个前端控件用例、一个自然语言 TaskDraft 用例和双 backend readback 用例证明。
- instruction 原样传递、Agent 数据工具、结构化追问、TaskCompiler、部分失败恢复、DataPreparationRecipe 自动匹配/沙箱回退和 SEQ-70 全部通过。
- DataPreparationRecipe 冻结用例必须证明自动误匹配为零、格式漂移回退、来源血缘完整、同输入同版本输出稳定，并量化同构来源上的模型调用减少与本地额外耗时。
- 最终探索性黑盒仅接收用户可见功能说明，由独立会话设计测试，本窗口在正式 Windows Electron UI 执行并保留证据。

数据整理专项必须覆盖：普通 CSV、多 sheet Excel、带仪器说明 TXT 首次 Agent 整理、保存严格 Recipe、同构文件零模型复用、非合同变化、关键结构漂移、同级候选选择、多文件部分失败、原始片段回看、撤销/重新整理、数据伪指令、Profile 机械兼容与 renderer 下游失败。硬门槛为自动误匹配 0、Recipe 输出可复现、同构来源第二次整理 0 模型调用、失败不污染原始数据/历史版本/其他成功文件。
