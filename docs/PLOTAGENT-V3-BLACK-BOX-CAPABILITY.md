# PlotAgent v3 黑盒能力说明

> 当前范围：34 张单图；不支持组合图。K25 已从前端、Agent capability、契约、双后端和导出链删除，仅为旧项目保留 `CHART_TYPE_REMOVED` 墓碑。

本文只描述用户可观察能力，不披露底层架构或实现原理。

## 1. 产品定位

PlotAgent v3 是 Windows 科研绘图 Agent。用户上传数据，通过图形库或自然语言明确指定图类并确认字段绑定；Agent 负责形成可确认任务并调用绘图引擎。任务可以是一张图、多个数据各生成一张图，或“数据 A 画 A 图、数据 B 画 B 图”这种显式异构批量。结果可导出 PNG、SVG，以及在合格 Origin 环境中原生可编辑的 OPJU。

v3 不提供开放式统计分析、拟合、任意数据清洗、任意代码执行、图像处理、组合图或自由画布。

## 3. 可观察工作流

1. 新建或打开本地项目。
2. 导入 CSV、TSV、TXT、DAT、XLS、XLSX 或 XLSM 中受支持的表格数据；Excel 的多个工作表分别成为可选择数据表，TXT 中识别出的仪器信息与数据块分别展示。
3. 在图形库选择图类，或在自然语言中对每个数据明确指定图类。
4. Agent 声明字段绑定；若信息不足，提出必要追问。
5. 用户确认后创建 v1 图；确认前项目无副作用。
6. 用户用自然语言或聚焦编辑修改标题、坐标轴、系列、图例及图类声明支持的参数。
7. 每次成功修改形成新版本；支持当前会话内可逆编辑的撤销与重做。
8. 导出 PNG、SVG 或原生可编辑 OPJU。

没有已选数据或当前图形时，Agent 不会获得可操作对象，界面应提示用户先选择或导入数据。已有数据但没有预选图类时，用户可以在指令中明确点名受支持图类；若仍存在多个合理图类候选，Agent 必须追问，不得擅自猜测、推荐并执行或替换成其他图类。

### 3.1 多数据任务

- **同类批量：** 多个兼容数据表使用同一张明确图类，各自生成一张图；单项失败不撤销已经成功的图。
- **异构批量：** 用户可在一句指令中明确指定“数据 A→图类 A、数据 B→图类 B”；每个子任务都必须绑定明确数据和明确图类，含糊项进入追问而不是猜测。
- **多数据同图：** 用户显式选择 2–8 个完全同构的数据表后，可在散点图、列散点图、箱线图、小提琴图、面积图、日期时间折线图或蜂群图中合并绘制；来源名称作为可追溯分组保留。
- 多数据同图不是任意 join，也不是组合图：字段名称、逻辑类型、单位、角色和顺序必须兼容；不兼容时明确拒绝，原始数据不被改写。

## 4. 公共编辑能力

仅开放 Matplotlib 与 Origin 都能准确表达并读回、且当前图类声明支持的动作：

- 创建图与重新绑定字段；
- 设置图标题；
- 设置轴标题、线性/Log10、范围、反向、刻度/网格、文字样式、对象可见性和刻度线方向中的适用项；
- 设置系列颜色、线宽、线型、符号、符号大小、填充/边缘、透明度和整体可见性中的适用项；
- 显示/隐藏图例及适用的共同位置；
- 设置数据标签、连续色板/色域和误差样式中的适用项；
- 设置图类专属的已声明参数；
- 导出 PNG、SVG、OPJU。

不支持的动作必须明确拒绝，不得近似映射到另一个属性。

## 5. 数据与科学边界

- 原始数据只读；为绘图需要的确定性宽/长表适配和封闭固定计算可形成可追溯 Plot Data。
- 双向误差棒使用 `X、中心值、X负误差、X正误差、Y负误差、Y正误差`；四列误差均为非负幅度，并直接保留为原生正负误差对象。
- 误差带使用 `X、中心值、下限、上限`。
- 时间序列与面积图使用一列公共 X/时间和一个或多个数值系列。
- 相关矩阵接受已经计算好的行标签、列标签和值，不替用户计算相关系数。
- Y 偏移堆叠线图使用宽表 `X + N 个 Y 系列`。
- 前后对比图要求 Subject、Before、After；Group 可选，身份标签必须保留。
- 不执行回归、检验、平滑、峰识别、基线校正、归一化、去噪或任意分析流程。

## 6. Agent 行为

- 内置 Agent 负责理解目标、检查必要的数据事实、选择受控的数据操作、提出必要问题，并生成可确认的单项或批量任务；用户确认后才执行。
- 用户可以给出一个完整目标，例如多份数据分别画不同图、先筛选/排序/变形/拼接或换算单位再绘图。Agent 可以在当前任务内多轮使用只读检查和确定性工具，但不能运行任意代码或直接修改原始数据。
- 对同一批量任务，已成功项会保留；技术失败只恢复失败项，不重复执行成功项。任何会改变字段、图类或科学定义的修订都必须再次确认。
- 用户确认前无副作用；失败不留下半版本。
- 对象、图类或字段真正歧义时追问；已明确的信息不重复追问。
- 模型或工具不可用、传输超时、取消或拒绝时显示真实状态，不伪造计划或结果；Agent 任务本身当前不设置总时长硬截止。
- 当前图、明确图 ID/版本、明确批次与明确选中集合可以作为目标；不存在组合图目标。

## 7. 导出与可编辑性

- PNG 与 SVG 为正式导出格式。
- OPJU 导出前先检测 Origin；不可用时在保存对话框之前给出诊断。
- 合格 OPJU 可由声明的 Origin 版本重开，包含实际使用的数据工作表和原生图对象。
- 坐标轴、系列、图例及适用对象可在 Origin 中继续编辑；不是 Matplotlib 图片嵌入。
- 导出成功后必须出现明确成功消息和产物路径/名称。
- 当前不支持将用户在 Origin 中另行修改的 OPJU 回导同步到 PlotAgent。

## 8. 证据边界

- 本文件描述能力，不声明当前候选已经验收通过。
- 工程测试、视觉审查、正式 Windows UI、Origin fresh-reopen 和 SEQ-70 分开记账，彼此不能替代。
- 任何证据只对记录的 commit、依赖、fixture、模型配置和 Origin 版本有效；产品代码变化后按影响范围重跑。
- 未在正式 Windows Electron UI 中实际执行并保存证据的用例必须记为 `UNVERIFIED`，不能由源码、单测、静态审计页或历史报告推定为 PASS。

## 9. 黑盒判定规则

- `PASS`：在正式桌面 UI 中实际执行，并有截图、ID/版本或导出产物证据。
- `FAIL`：观察到产品行为不符合本文件要求。
- `BLOCKED`：测试环境阻止执行，且不是产品行为失败。
- `UNVERIFIED`：未执行或证据不足。

“测了”不自动等于 PASS；必须同时观察到预期结果。

当前桌面产品与本地绘图引擎共享同一 Engine Profile 和动作边界；SDK/API/MCP 的产品化入口不属于当前正式桌面黑盒范围，不能由底层服务存在推定为已交付能力。
