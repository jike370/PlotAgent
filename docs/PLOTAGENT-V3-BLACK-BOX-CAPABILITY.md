# PlotAgent v3 黑盒功能与能力边界

> 用途：由不了解项目实现的测试人员，仅通过 Windows 桌面界面和正式导出文件判断产品是否达标。
> 适用范围：PlotAgent v3，2026-08-11 冻结范围。
> 禁止事项：验收人员不得以源码、内部文件、开发脚本、数据库或开发者口头说明代替可见产品证据。

## 1. 产品目标

PlotAgent v3 是面向数值型科研数据的绘图 Agent。用户可以导入数据、选择图形、确认字段作用，通过自然语言或聚焦编辑创建和修改图，并导出 PNG、SVG 以及可在 Origin 中继续编辑的 OPJU。

产品应同时满足：

- Agent 能把用户意图变成范围明确、可确认、可恢复的绘图任务。
- 图形结果符合所选图形的科学语义，不静默更换图形或字段作用。
- PNG、SVG 与 OPJU 表达同一份数据和同一组已确认修改。
- OPJU 中保留可编辑的数据、图页、坐标轴、系列、图例和适用的专属对象，不以嵌入图片冒充可编辑图。

PlotAgent 不是电子表格、统计分析平台、图像处理软件或任意代码执行工具。

## 2. 正式启动与测试隔离

### 2.1 当前正式测试入口

在仓库 `D:\plotv3` 中执行：

```powershell
pnpm dev
```

验收必须操作打开的 PlotAgent Electron 桌面窗口。`pnpm dev:web`、浏览器预览页、静态 HTML 审计页和开发脚本都不是黑盒产品入口。

当前仓库不提供已经签名、可作为验收基线的 Windows 安装包。若另行构建安装包，必须在报告中记录安装包完整路径、文件哈希和版本，不能与上述源码测试入口混用。

### 2.2 安全进入首次空状态

- 新建一个名称唯一的项目，例如 `BB-<日期时间>`。
- 不删除、不重命名、不复用已有用户项目。
- 不清空应用数据目录，不卸载软件，不覆盖已有 `.plotproj`。
- 可以使用首页“示例”创建独立示例项目，也可以用“导入”创建新项目。
- 重启恢复测试必须重新打开同一个测试项目，并记录重启前后的项目名、数据表名、图 ID 和版本。

## 3. 用户可见主流程

1. 新建或打开项目。
2. 导入一份或多份数值数据。
3. 明确选择图形，或在自然语言中明确图形编号/名称。
4. 确认字段映射。
5. 查看 Agent 任务计划及作用范围。
6. 确认后执行；失败时保留成功项，并继续未完成项。
7. 通过自然语言或聚焦编辑继续修改。
8. 导出 PNG、SVG 或 OPJU。

任何一步缺少必要字段、对象或范围时，软件应提出必要问题或明确拒绝，不能静默猜测。

## 4. 数据导入

### 4.1 正式格式

- Excel：`.xls`、`.xlsx`、`.xlsm`
- 文本数据：`.csv`、`.tsv`、`.txt`、`.dat`
- 一个 Excel 中的多个工作表保持为独立数据表。
- 支持一次选择多个文件；部分文件失败时保留成功导入的文件并列出失败项。

### 4.2 必须可观察的行为

- 数据表名称显示为可理解的“文件名 > 工作表/数据块”，不暴露内部哈希。
- 显示字段名、逻辑类型、物理类型、单位建议和基本质量摘要。
- 原始数据只读；绘图、改图和导出不修改源文件。
- 同一文件内容变化后重新导入，形成新数据版本，不静默改变已有图。
- 数据区、表头或分隔方式确有歧义时，给出原因并要求确认。
- Excel 公式、宏、外部链接和数据连接不执行、不刷新。

### 4.3 不承诺

- 任意单元格编辑、公式编辑、跨表 join、透视、任意聚合或通用数据清洗。
- Parquet、HDF5、MAT、NetCDF、NPY/NPZ、图片、地图或科研影像输入。
- 隐式补值、去重、单位换算、异常值删除或任意表达式计算。

## 6. 公开绘图与编辑能力

同一项能力只有在当前图形的聚焦编辑界面或 Agent 可用能力中明确出现时才算支持。不同图形不必开放相同参数。

- 创建图：选择图形，绑定字段，生成第一个图版本。
- 更新字段：改绑当前图所需字段，产生新版本。
- 标题：设置或隐藏图标题。
- 坐标轴：设置轴标题、线性/Log10、固定范围和反向显示中的适用项。
- 系列样式：设置颜色、线宽、线型、符号和符号大小中的适用项。
- 图例：显示/隐藏；图内、右侧或底部中的适用位置。
- 图形专属参数：只开放当前图形声明的参数，例如色带、阈值、分面列数、Pareto 参考百分比等。
- 安全文本标注：在支持的图或组合图中添加文本标注。
- 导出：PNG、SVG、OPJU。

编辑必须满足：

- 用户确认前不改变项目版本。
- 成功编辑产生新版本；失败不留下半成品版本。
- 作用对象必须是当前图、明确选择的图、明确批次或明确组合图。
- 不支持的参数应明确拒绝，不能近似映射到另一个属性。
- Matplotlib 与 Origin 不都能准确表达和读回的属性，不属于公开能力。

## 7. 图形专属科学边界

- K15、K16、K13、K14、K11、S61 等只执行图形定义不可分割的固定计算。
- K21 只绘制用户提供的相关矩阵，不从原始表计算相关系数。
- K22 只绘制规则网格，不把散点静默插值成网格。
- S01 只绘制用户提供的生存阶梯、区间和风险人数，不执行 Kaplan–Meier 估计或检验。
- S21 只绘制用户提供的效应量、区间和权重，不执行 meta-analysis。
- S34 不执行阻抗拟合、平滑或参数估计。
- 不执行回归拟合、统计检验、峰识别、基线校正、归一化、去噪或任意分析流程。

用户需要先在其他软件中完成不属于上述固定计算的数据整理与科学分析，再把结果字段导入 PlotAgent。

## 8. Agent、任务计划与项目上下文

### 8.1 模型服务

- 本地项目、手动绘图、聚焦编辑和 PNG/SVG 导出不要求在线模型。
- 自然语言绘图/改图要求用户配置可用的模型服务。
- “本地 Core 已连接”与“模型服务已配置”是不同状态，不能互相冒充。
- 模型不可用、超时或拒绝时必须给出明确状态，不能伪造计划或完成结果。

### 8.2 任务行为

- 简单明确任务可以生成单步计划；多图、批量或多步骤任务应展示范围和步骤。
- 用户确认前无副作用。
- 一个批次可以部分成功；成功项保留，恢复时只继续失败或未开始项。
- 对象或字段真实歧义时提出必要问题；已经明确的信息不得重复追问。
- 未明确图形类型的泛化“画图”请求应要求选择图形，不能私自推荐并执行。
- 项目切换或新请求使旧请求失效后，迟到结果不得覆盖当前任务。
- 项目重启后，已保存的数据身份、图版本和最近提交图应恢复。

### 8.3 作用对象

可验收的作用对象包括：当前数据、当前图、明确图 ID/版本、明确批次、明确选择集合和已创建的 K25 组合图。复杂跨轮指代只有在界面计划中显示为唯一、正确的具体对象时才算通过；不能只凭模型回复文字判定。

## 9. 批量与组合图

### 9.1 批量

- 多文件或多工作表可为兼容数据批量创建同一种明确选择的图。
- 字段结构不兼容的成员进入待补充或失败，不能套用错误映射。
- 批量允许部分成功，恢复时不得重复执行成功项。
- 批次结果应显示实际成员、状态和可继续范围。

### 9.2 K25 组合图

- 输入 2–4 张已经创建并渲染的不同图。
- 候选不足两张时不能创建，并说明还缺多少张。
- 创建成功后显示组合图 ID 和版本，并允许打开组合图。
- 组合图保留各子图数据和可编辑对象；不接受把子图截图拼成 OPJU。
- 当前不承诺任意嵌套组合、自由拖拽跨行跨列、图片与数值图混排或任意共享轴。

## 10. 导出

### 10.1 正式格式

- PNG：栅格图。
- SVG：矢量图。
- OPJU：在受支持 Origin 环境中继续编辑的项目。

PDF、EPS、EMF 不属于当前正式导出承诺。

### 10.2 OPJU 验收要求

- 导出前检测 Origin；不可用时在保存对话框之前给出可操作诊断。
- 不连接、修改或关闭用户已经打开的 Origin 窗口。
- OPJU 非空，可由 Origin 重新打开。
- 图页和实际使用的数据都存在；轴、系列、图例及适用对象可继续编辑。
- 导出失败不发布半成品。
- 当前不承诺把用户在 Origin 中修改后的 OPJU 重新导入并同步回 PlotAgent。

## 11. 隐私与联网边界

- 项目、源数据、图和导出文件默认保存在本机。
- 无需注册 PlotAgent 账号即可使用本地功能。
- API key 不写入项目、对话或导出文件，也不在界面回显。
- 完全本地使用时不产生模型请求。
- 使用在线模型时，界面明确显示模型服务状态；不得暗示所有数据默认上传。

## 12. 黑盒验收清单

### 12.1 证据规则

- 每个 PASS 必须有正式桌面窗口截图、可复现步骤或正式产物；“测了”不等于 PASS。
- 没测或证据不足记 UNVERIFIED；观察到不符合要求才记 FAIL；环境无法执行记 BLOCKED。
- 静态视觉审计页只能帮助挑选复测对象，不能替代正式 UI 黑盒证据。
- 报告记录测试提交、启动命令、Windows/Origin/模型服务版本、项目名及产物路径。

### 12.2 必测域

1. 新项目、项目搜索/置顶/重命名/删除菜单和重启恢复。
2. CSV、多工作表 XLSX、一次多文件和一个歧义文本导入。
3. 38 图分别用兼容数据创建一次，核对字段角色和图形身份。
4. 对支持项执行标题、轴、系列、图例、专属参数和标注动作；确认版本与读回。
5. K04 默认态不应无故出现色带；用户明确开启色带后才出现。
6. K06 同时具有水平与垂直误差棒；K14 不出现无关的边缘竖线。
7. 涉及图例的代表图，图例同时提供与系列对应的形状/线型/颜色样例和文本。
8. 选至少一个分组、柱状、分布、矩阵、双轴、多系列和多面板代表图，在 Origin 中人工修改后保存重开。
9. 创建两张图并组成 K25，检查组合图 ID、版本、子数据和原生对象。
10. 建立三成员批次，其中一项失败；确认部分成功和只恢复失败项。
11. 用模型执行明确创建、复合编辑、必要追问、错误目标拒绝、超时后新请求等任务。
12. 关闭应用并重启，检查项目、数据身份、最近图 ID/版本和可见预览。
13. 导出 PNG、SVG、OPJU；用 Origin 打开 OPJU 检查图和数据可编辑。
14. 请求拟合、任意改单元格、任意代码、图片处理和不支持图形，确认明确拒绝。

### 12.3 38 图视觉签名

38 图机械生成和读回通过后，仍需人工分别审查默认态和代表编辑态。视觉签名至少确认：

- 图形类型、数据几何和字段语义正确。
- 没有额外出现未请求的系列、色带、边界线、连接线或参考对象。
- 图例样例与实际系列一致。
- 双轴、误差、区间、分面、组合与矩阵的关系正确。
- Matplotlib 与 Origin 表达同一项用户动作；允许产品外观不同，但不允许语义不同。
