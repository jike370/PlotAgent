# PlotAgent v3 功能与能力边界说明

> 文档用途：供不了解项目内部实现的测试人员进行黑盒验收  
> 适用产品：PlotAgent v3 Windows 桌面版  
> 文档日期：2026-08-09  
> 限制：本文只描述用户可观察的功能、输入输出和能力边界，不包含任何内部架构、实现原理或技术选型。

## 1. 产品定位

PlotAgent v3 是面向通用科研用户的数值数据绘图桌面软件。用户可以在项目对话中导入一份或多份数据，明确选择图形，确认字段在图中的作用，然后生成、批量审阅、自然语言修改并导出科研图。

产品的主要价值是：

- 用对话组织单图、批量绘图、改图和导出任务。
- 在多轮对话中持续识别当前图、选中图和上一批图。
- 对批量任务先展示计划和范围，再由用户确认执行。
- 在部分任务失败后保留成功结果，只继续未完成部分。
- 导出 PNG、SVG 和可在 Origin 中继续编辑的 `.opju`。

PlotAgent 不是统计分析平台、电子表格编辑器、图像处理软件或任意代码执行工具。

## 2. 使用入口与项目

### 2.1 启动与账户

- 软件无需注册账号即可进入主界面并使用本地项目和本地绘图能力。
- 首次空状态应提供“示例”“导入”和打开已有 `.plotproj` 的入口。
- 示例使用本地合成数值数据；打开示例后应创建可修改的项目副本。
- 使用在线模型能力时可以要求配置可用的模型服务；模型不可用不应阻止手动导入、绘图、编辑和 PNG/SVG 导出。
- 应用按单实例工作；重复启动时应回到已有窗口。

### 2.2 项目管理

- 左侧项目列表只常驻显示项目名称。
- 项目支持新建、搜索、打开、置顶、重命名和删除。
- 项目操作位于项目项的三点菜单；悬停时可以显示项目摘要。
- 一个项目可以包含多份数据、多张图、多个绘图批次和多轮对话。
- 成功操作应自动保存；关闭并重新打开应用后，已提交结果仍应存在。
- `.plotproj` 用于保存和转移 PlotAgent 项目；它不是图形导出格式。

## 3. 数据导入

### 3.1 支持范围

首阶段重点支持：

- Excel：`.xlsx`、`.xls`、`.xlsm`，包括多工作表。
- 文本数据：`.csv`、`.tsv`、`.txt`、`.dat`。
- 含仪器说明、表头、数据区和尾部说明的文本文件。
- 一次导入多个文件；结构兼容时可用于批量绘图。

### 3.2 可观察行为

- 导入后应列出识别到的数据表、字段、数据类型、单位建议和质量摘要。
- 多工作表默认保持为独立数据表，不应静默合并。
- 仪器前导信息和尾部文本不应被误当作数值数据行。
- 数据区、表头或分隔方式存在同等合理候选时，应向用户提出必要问题，而不是静默猜测。
- 原始数据保持只读；绘图、改图和导出不能修改源文件或任意改单元格。
- 同一源文件内容改变后重新导入，应作为新的数据版本处理，不能静默改变已有图。
- Excel 公式、宏、外部链接和数据连接不得执行或刷新。

### 3.3 不支持范围

- 不提供任意单元格编辑、电子表格公式编辑或通用数据清洗工作台。
- 不自动跨工作表 join、按名称猜测合并或执行任意表达式。
- 不支持把图片、显微图、遥感图或地图文件作为首阶段绘图输入。
- Parquet、HDF5、MAT、NetCDF、NPY/NPZ、TIFF、PNG、JPEG、GeoJSON 等不属于首阶段正式输入承诺。

## 4. 绘图主流程

标准流程为：

1. 导入数据。
2. 用户明确选择图形，或在指令中明确写出图形名称/编号。
3. 确认一次字段映射，例如 X、Y、分组、误差、颜色或面板字段。
4. 检查任务范围和计划。
5. 用户确认后绘图。
6. 在对话中继续修改、批量审阅或导出。

验收时应确认：

- 软件不会静默替换用户选择的图形。
- 字段不满足图形要求时，应说明缺少什么并进入待补充状态。
- 同一段对话可以产生多张图或多个批次，不强制“一轮对话只生成一张图”。
- 图表默认覆盖完整有效数据范围，并根据数据动态调整坐标和布局。
- 组数、字段顺序、标签长度或数据范围变化时，不应依赖固定数量或固定位置参数。

### 5.4 图形科学边界

- “给定”表示软件只绘制用户已经提供的结果，不负责计算该结果。
- K05、S05 不执行回归或剂量—反应拟合。
- K21 不从原始表计算相关系数，只绘制用户提供的矩阵。
- K22 不把散点自动插值为规则网格。
- S01 不执行 Kaplan–Meier 估计，只绘制用户提供的阶梯、区间和风险人数。
- S21 不执行 meta-analysis，只绘制用户提供的效应量、区间和权重。
- S25、S31、S34 不执行峰识别、平滑、基线、拟合或阻抗建模。
- S07 根据用户提供的 log2FC 和 p/q 值按显式阈值分类绘图，不执行差异分析。

## 6. 批量绘图

- 用户可以上传多份数据或包含多个工作表的 Excel，并为兼容数据批量绘制同一种图。
- 一个批次只包含一种用户明确选择的图形。
- 批次只复用一次字段映射；字段集合、类型、单位或语义不兼容的成员应进入待补充或失败状态，不能套用错误映射。
- 批量结果应使用统一的类别颜色和样式规则；各图坐标默认按自身数据自动缩放。
- 批量审阅应提供真实缩略图、状态筛选、多选、异常标记和失败项继续入口。
- 批量允许部分成功；继续任务时不得重做已经成功的图。
- 用户可以明确排除部分图后导出；排除范围必须可见。

## 7. 自然语言与任务 Agent

### 7.1 支持行为

- 支持中文、英文以及中英混合科研术语。
- 支持创建图、修改图、创建批次、修改批次和导出等产品内任务。
- 多步骤或批量任务执行前应展示作用范围、步骤和待确认状态。
- 支持“当前图”“选中的图”“上一批”“这些图”“除第三张外”等跨轮次作用对象表达。
- 指令有唯一合理对象时可以继续；对象、范围或字段存在真实歧义时应提出必要问题。
- 对话中应显示真实进度、成功项、失败项、可继续状态和最终变更摘要。
- 应用重启后，未完成任务、已确认范围和成功结果不应丢失。

### 7.2 明确限制

- Agent 不应在用户未明确选择时静默推荐、猜测或替换图形类型。
- Agent 不运行任意 Python、SQL、脚本、命令或用户代码。
- Agent 不提供开放式工具循环，也不自行浏览文件系统或任意网站。
- Agent 不能绕过字段确认、范围确认、版本冲突或产品能力限制。
- Agent 不执行任意数据处理、统计检验、相关分析、拟合、平滑、归一化或单位换算。
- 模型服务不可用时，应明确提示；不能伪造已完成的模型结果或任务进度。

## 8. 改图能力

### 8.1 通用编辑

图形声明支持时，可通过自然语言或聚焦编辑界面修改：

- 图题、X/Y 轴标题与单位显示。
- 坐标范围、线性/对数坐标、刻度与显示精度。
- 字体、画布尺寸和已提供的发表规格。
- 图例显示与位置。
- 系列颜色、线宽、线型、点大小、符号形状和符号内部样式。
- 柱填充、边线、柱宽和组间距。
- 误差棒、区间带、调色板和色带。
- 双 Y 轴样式、分面布局和 Y 偏移。
- 图形明确开放的阈值、阶梯方式等专属参数。
- 安全的文本、箭头、参考线、参考区间、峰标签、显著性括号和面板编号。

### 8.2 编辑规则

- 一条指令必须作用于界面中明确显示的当前图、选中图或批次范围。
- 成功修改生成新版本；原版本应可追溯，失败修改不得留下半成品。
- 修改数据范围、组数或长标签后，柱、图例、色带、坐标标题和面板不应重叠或越界。
- 对数坐标只改变坐标显示，不应静默改写原始数据。
- 图形未声明支持的编辑应明确拒绝，而不是转成任意 Origin 属性修改。

### 8.3 当前不支持

- 不支持任意 Origin 属性路径、任意图层 JSON 或任意改单元格。
- 不提供自由矢量绘制工具。
- 不提供开放式组件搭建器、任意图层增删/排序或空白画布搭图。
- 不支持科研图像 ROI、通道、比例尺、裁剪或图片混合面板。

## 9. 计算与数据处理边界

PlotAgent 只保留图形不可分割且定义封闭的固定计算，例如直方图分箱、箱线统计、密度轮廓、ECDF、百分比堆积或混淆矩阵计数。计算口径应随图形明确，不扩展为通用分析工作流。

以下能力不属于 v3 首阶段：

- 回归拟合、非线性拟合、剂量—反应拟合和拟合优度分析。
- 统计检验、显著性计算、相关分析和 meta-analysis。
- Kaplan–Meier 估计、生存检验或风险人数推导。
- 平滑、基线校正、去噪、归一化、插值、峰识别和异常值处理。
- 任意筛选、连接、透视、聚合、公式、宏或可编程数据管线。
- 隐式删除缺失值、补值、去重、单位换算或修改原始数据。

用户可以在其他软件中完成这些计算，再把结果字段导入 PlotAgent 绘图。

## 10. 组合与多面板边界

- K24 支持具有明确分面字段的同构分面图。
- K25 支持输入已经明确分成面板的多面板数值图。
- 支持图形内部已经定义的双轴、风险表和偏移堆叠结构。
- 当前不承诺任意异构图自由拼装、跨行跨列拖拽、嵌套面板、局部放大、任意共享轴或图像—数值混合排版。
- 当前不开放用户自定义图形搭建器。

## 11. 导出

### 11.1 正式格式

- PNG：栅格图。
- SVG：矢量图。
- OPJU：可在受支持的 Origin 环境中继续编辑的原生项目。

不提供 PDF、EPS、EMF 等正式图形导出入口。

### 11.2 OPJU 行为

- OPJU 应包含目标图实际使用的数据和可编辑图形对象，不能用嵌入 PNG/SVG 冒充原生图。
- 导出前应检测 Origin 是否可用；不可用时只禁用 OPJU，PNG/SVG 仍可使用。
- 一份 OPJU 可以包含一个或多个被明确选择的图页。
- 导出失败时不能发布半成品文件。
- PlotAgent 不连接或关闭用户已经打开的 Origin 窗口。
- PlotAgent 不导入、解析或同步用户修改后的 `.opju`；首阶段只负责导出。

## 12. 隐私与联网的用户可见边界

- 项目、原始数据、图和导出文件默认保存在本机。
- 不注册账号也可以使用本地项目和本地绘图能力。
- API key 不应写入项目文件、对话内容或导出图中。
- 用户选择完全本地模式时，不应产生远程模型请求。
- 使用在线模型时，界面应明确模型服务状态；不得声称所有科研数据默认都会上传。
- 软件不应上传项目、图表或诊断包作为默认行为。

## 13. 黑盒验收建议

### 13.1 测试原则

- 只通过正式桌面界面操作，不查看源码、数据库、开发日志或内部文件结构。
- 使用干净的新项目，不依赖预先生成的隐藏对象。
- 所有“完成”必须有界面结果或正式导出文件，不接受解释性文字代替功能。
- 不因测试人员知道预期而替软件补字段、补状态或手工修复项目。

### 13.2 最小测试数据集

至少准备：

1. 普通 CSV：两列数值，测试单图与自然语言改图。
2. 多工作表 Excel：三个同构工作表，测试一次映射和批量绘图。
3. 仪器 TXT：包含前导说明、单位、数据块和尾部文本。
4. 分组数据：由两组扩展到三组或五组，测试动态布局。
5. 预计算结果：曲线与区间、相关矩阵、森林图区间或生存阶梯中的至少一种。
6. 歧义数据：两个都可能作为 Y 的数值字段，测试必要追问。

### 13.3 必测任务

1. 无账号启动，创建并重命名项目。
2. 导入 CSV、Excel 多工作表和仪器 TXT。
3. 明确选择图形，确认一次字段映射，生成单图。
4. 用三个同构工作表批量绘制同一图形。
5. 修改标题、颜色、符号、坐标范围和对数坐标中的适用项。
6. 让一项批量成员失败，确认成功项保留；补充信息后只继续失败项。
7. 下一轮使用“上一批除第三张外”等指令修改范围。
8. 关闭并重启应用，继续未完成任务。
9. 导出 PNG、SVG 和 OPJU，并在 Origin 中打开 OPJU 检查数据与可编辑对象。
10. 提出拟合、任意改单元格、图像处理和任意代码请求，确认软件明确拒绝或说明不支持。

### 13.4 失败判定

出现以下任一情况，应记录为失败：

- 静默选择或替换图形。
- 字段映射错误但未要求确认。
- 修改了原始数据或源文件。
- 批量恢复时重做已成功项。
- 对错误对象或错误范围执行修改。
- 应用重启后计划、确认或已完成结果丢失。
- 显示假进度、占位结果或只返回说明文字。
- 分组数量或数据范围变化后出现柱重叠、标签/图例/色带越界等明显冲突。
- OPJU 只是嵌入图片、无法继续编辑或使用了错误数据。
- 在未明确告知的情况下执行拟合、清洗、单位换算或其他科学计算。
- 把不支持能力包装成“已完成”或静默降级。
