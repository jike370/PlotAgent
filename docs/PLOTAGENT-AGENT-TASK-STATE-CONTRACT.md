# PlotAgent Agent 任务状态合同

> 状态：2026-08-20 用户确认的权威产品合同。
>
> 适用范围：Agent 规划、确认、执行、部分失败、修订、跳过、取消、恢复、重启和用户可见错误。任何实现、测试或发布结论不得与本合同冲突。

## 1. 目标

任务状态机的职责是让用户始终知道：系统理解了什么、将修改什么、哪些项目已经成功、哪些尚未执行、为什么停止，以及下一步可以做什么。模型负责语义理解，Core 负责权威状态、权限、幂等和项目事务；任何一方都不能用自然语言结论代替真实状态。

## 2. 权威来源与冲突

### 2.1 图类来源

- 只有界面图类选择：使用所选图类。
- 只有当前自然语言明确指定图类：使用自然语言指定的图类。
- 两者一致：直接规划。
- 两者冲突：展示两个具体图类并追问一次；不得静默覆盖、自动猜测或用历史上下文替换当前指令。
- 用户最终确认的计划是本次执行授权的权威来源。

界面选择是显式上下文，不是不可修改的隐藏硬约束；自然语言也是显式意图。二者冲突时没有默认胜者。

### 2.2 其他权威顺序

1. 已确认且版本匹配的计划；
2. 当前用户消息中的明确要求；
3. 当前界面明确选择的数据、图和对象；
4. 当前任务内已确认且未被修改的上下文；
5. Agent 推断。

图类硬合同、安全边界和数学不变量不因上述顺序而失效。冲突必须解释并追问或拒绝，不能静默修改要求。

## 3. 计划确认与修订

### 3.1 首次执行

正式项目写入前必须展示可读计划，至少包含任务项、数据来源、图类、字段绑定、必要数据处理和将产生的正式对象。用户确认后，ExecutionGrant 仅授权该计划版本。

### 3.2 无副作用的缩减

当用户只做以下操作时，不重复展示完整确认计划：

- 跳过失败项；
- 放弃尚未执行项；
- 接受已成功结果；
- 保留成功项并结束任务。

这些操作不产生新副作用。用户的明确消息本身就是缩减授权，Core 直接收口任务。已成功项不得重新执行，项目 revision 不得增加。

### 3.3 必须重新确认的修订

以下变化必须生成下一版本计划并重新确认：

- 修改字段绑定、数据来源或数据处理；
- 替换图类；
- 修改绘图或导出参数；
- 新增任务项；
- 重试时采用不同语义方案；
- 任何会产生新的正式项目副作用的变化。

技术重试若参数、权限和幂等键均不变，不形成语义修订。

## 4. 用户可见终态

产品层必须区分以下终态，不能全部折叠为 generic success、failure 或 cancelled。

| 用户可见终态 | 语义 | 项目结果 |
|---|---|---|
| 已完成 | 所有确认项成功 | 保留全部成功结果 |
| 已完成，部分项目已跳过 | 至少一项成功；其他失败或未执行项经用户明确放弃 | 保留成功结果，不重复执行 |
| 等待处理 | 存在失败或缺少语义，用户尚未选择修订、重试或跳过 | 保留已成功结果 |
| 已取消 | 用户通过产品显式停止控制终止任务 | 按原子边界保留已提交结果 |
| 失败 | 没有可交付结果且当前任务无法继续 | 不伪造成功版本 |

内部状态可以更细，但必须稳定投影为上述语义。模型不得提交“已取消”终态；整任务取消只能由显式停止控制触发。

## 5. 取消与撤销

- 用户点击停止后，不再启动新工具或新任务项。
- 尚未执行的任务项取消。
- 正在执行的原子项目写入在安全一致性边界完成后停止，不能留下“产物已写入但台账未知”的状态。
- 已成功提交的任务项保留。
- 执行前停止时项目完全不变化。
- 停止不是撤销。用户需要删除已成功结果时使用独立撤销操作。
- 模型返回 `cancelled`、用户自然语言说“跳过某项”或“只保留成功项”，均不能替代产品显式停止控制。

## 6. 自动恢复边界

| 失败类型 | 默认处理 | 是否调用模型 | 是否重新确认 |
|---|---|---:|---:|
| 网络抖动、连接重置、可重试传输超时 | 程序自动重试一次 | 否 | 否 |
| 同一参数可安全重放的执行错误 | 提供“重试” | 否 | 否 |
| 数据、字段、图类或参数语义不成立 | 证据充分时 Agent 自动修订；缺少用户事实时追问 | 是 | 修订计划必须重新确认 |
| 项目 revision、对象版本或 lease 冲突 | 停止写入并重新读取上下文 | 视新上下文而定 | 语义或目标变化时是 |
| 相同失败重复或无进展 | 停止自动尝试并交还用户 | 否 | 不适用 |
| 任务级预算耗尽 | 当前任务明确失败；用户可用新任务重试 | 否 | 新任务重新确认 |

禁止通过关键词、正则、隐式模板替换或参数降级改变用户目标。确定性重试只能重放同一授权语义。
已证明 `known_none`、不需要用户补充事实且失败证据完整的语义冲突，可以自动进入一次受限的
Agent 修订；这不是原计划重试。Agent 只能修订未完成项并保留成功项，新计划必须重新确认。
只要缺少字段含义、目标选择或其他用户事实，系统就必须停止自动修订并追问。

## 7. 错误与可观察性

Agent 无法产生合法计划或执行失败时，界面必须同时说明：

- 失败阶段；
- 失败类别：模型服务、上下文冲突、数据不足、计划校验、执行、验证或项目并发；
- 项目是否发生变化；
- 已保留的成功项；
- 可执行的下一步；
- 稳定诊断 ID。

界面提供“重试本轮”“修改要求”或适用的“跳过失败项”，但不盲目无限重试。旧错误在后续成功后不得继续冒充当前状态。

## 8. 状态转换矩阵

| 起点 | 事件 | 必须到达 | 禁止行为 |
|---|---|---|---|
| 新任务 | 信息充分 | 等待确认 | 确认前写正式项目 |
| 新任务 | 图类选择与自然语言冲突 | 等待输入 | 静默选择任一图类 |
| 等待输入 | 用户回答 | 等待确认或再次精确追问 | 新建无关任务 |
| 等待确认 | 用户确认 | 执行中 | 执行其他计划版本 |
| 等待确认 | 用户修改 | 调查中，生成下一版计划 | 沿用旧授权 |
| 执行中 | 全部成功 | 已完成 | 重复执行成功项 |
| 执行中 | 部分成功、部分失败 | 等待处理 | 丢失成功项或整任务失败 |
| 等待处理 | 仅跳过失败项 | 已完成，部分项目已跳过 | 再确认或重复成功项 |
| 等待处理 | 修订失败项 | 等待重新确认 | 未确认即执行新方案 |
| 等待重新确认 | 用户确认 | 仅执行新增或失败项 | 重跑成功项 |
| 任意可取消阶段 | 用户点击停止 | 取消中，随后统一到已取消；已提交结果留在该 checkpoint | 模型自行取消或回到部分失败 |
| 已取消 | 新用户任务 | 新任务正常规划 | 继承旧 busy、错误或授权 |
| 进程重启 | 存在耐久非终态任务 | 恢复到准确阶段 | 从头执行或伪造终态 |
| 任意阶段 | stale response 晚到 | 丢弃旧响应 | 覆盖新计划或新对象 |

## 9. 必须覆盖的确定性验收组合

每个组合都要验证任务状态、任务项状态、project revision、plot ID/version、attempt count、ExecutionGrant、receipt 和重启后状态。

1. 单项创建成功；
2. 单项编辑成功；
3. 图类上下文一致；
4. 图类上下文冲突并追问；
5. 批量全部成功；
6. 批量部分成功后仅重试失败项；
7. 批量部分成功后跳过失败项；
8. 修订计划重新确认且不重复成功项；
9. 规划阶段显式停止；
10. 执行前显式停止；
11. 原子任务项执行期间停止；
12. 取消后立即提交新任务；
13. 传输错误自动重试一次；
14. 语义错误不做确定性盲重试；
15. 相同失败无进展停止；
16. 等待确认、部分成功、取消中和完成后分别重启；
17. 旧模型响应晚到不覆盖当前任务；
18. 所有错误卡包含阶段、变化、保留项、下一步和诊断 ID。
19. 修复无需追问时可直接形成修订计划并进入重新确认；
20. 可恢复 blocker 在普通规划与修复阶段分别回到原准确阶段；
21. 预算耗尽和不可恢复 blocker 不展示伪恢复入口；
22. 规划、追问、执行、验证、交付和取消中断后逐阶段重启。

确定性状态机测试必须先于真实模型和 UI 黑盒。真实模型评测证明语义表现；它不能替代 Core 状态机正确性。

逐场景的起点、事件、终点、项目不变量和确定性测试位置，见
《[PlotAgent Agent 任务状态与确定性测试矩阵](PLOTAGENT-AGENT-TASK-STATE-MATRIX.md)》。

## 10. 发布原则

- 不删除失败用例；
- 不因发布时间放宽状态、幂等、项目一致性或用户可见错误断言；
- 不把未执行记为通过；
- 不用静态页面、源码判断或单元测试替代正式 UI 观察；
- 不用真实模型的偶然一次成功证明确定性状态机；
- 新问题按合同归类后审计同类转换，不做只覆盖单个提示词的补丁。

## 11. 实现投影（2026-08-20）

- `partial` 只表示“等待处理”，不再充当用户接受部分结果后的终态。
- 所有项目成功时，耐久任务以 `completed_verified` + `completion.outcome=all_succeeded`
  收口；用户明确放弃其余项目时，以
  `completed_verified` + `completion.outcome=completed_with_skips` 收口。界面分别显示
  “已完成”和“已完成（含跳过项）”。
- “跳过失败项/只保留成功项”仍由 Agent 理解自然语言，但 Core 不按关键词路由。Core
  比较新旧结构化意图：只有新意图恰好保留全部已验证成功项、删除全部非成功项，且保留项
  的字段、图类、数据处理和视觉动作逐项相同时，才直接结束；否则生成下一版计划并重新确认。
- 显式停止永远收口为 `cancelled`。已提交成功项保留在任务台账和项目中，界面必须显示保留
  数量；执行前停止才显示“项目未发生更改”。
- `transient_external` 失败由 Core 对同一授权项自动重试一次，不启动 Agent；第二次相同失败
  停止自动尝试。确定性技术修复、语义修订和用户操作继续遵循第 6 节。
- 创建任务中的 UI 图类选择只是 Agent 默认值，不是权限边界。最新用户指令明确指定另一
  个闭集图类时，Agent 直接提交该图类的 `intent_ready`，Core 校验其仍属于本次 34 图闭集，
  不要求用户回到 UI 重选，也不为这类已明确覆盖产生额外 `needs_input`。只有自然语言仍有
  多个实质候选时才追问。已选 `@图N` 的真实 plot ID/version 仍是编辑任务硬目标。
- 最终计划是创建图类的用户可见权威：单一图类回投 Composer；多个不同图类显示“多图任务”；
  同图类批量仍显示该图类。单一投影成为续轮结构化默认；“多图任务”不得暗中继续发送计划前
  的单一 profile。修订、拒绝、执行、重启与迟到响应必须遵守同一耐久投影规则。
- 每个执行失败写入稳定诊断 ID、失败类别和 side-effect state；任务卡同时显示失败阶段、
  项目是否变化、保留结果和下一步。
