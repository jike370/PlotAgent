# PlotAgent 任务型对话与交互验收契约

> 状态：产品决定已确认，2026-08-13。数据契约、桌面错误信息、任务型对话、可逆编辑撤销/重做和相邻版本比较已经实现；正式 Windows Electron 黑盒仍是最终验收依据。本文分别标明“已实现”“待黑盒确认”和“后续能力”，不得以目标描述冒充当前能力。

## 1. 目标

PlotAgent 采用“任务型聊天”，不是开放式陪聊，也不是把表单简单放在输入框旁。对话负责表达理解、追问、确认、执行和结果；结构化卡片负责精确选择与确认；本地权威对象、validator、事务和任务运行时继续决定能否执行。

用户仍然明确选择图形类型。Agent 可以说明缺失条件、兼容性和字段角色，但不得主动推荐、猜测或替换图形类型。

## 2. 核心交互循环

一轮标准交互必须形成同一条连续时间线：

1. 用户发送自然语言需求，消息立即以用户气泡进入对话；
2. Agent 显示当前正在处理的真实阶段；
3. 条件不足时，Agent 在对话中提出一个必要问题，并嵌入相应的数据上传、图形选择或字段选择控件；
4. 条件齐全时，Agent 声明对需求的理解，并给出字段绑定或变更确认卡；
5. 用户确认后，任务才进入有副作用的本地执行；
6. 同一条执行状态消息随真实阶段更新；
7. 完成后，该消息收口为结果卡，说明产物、版本、警告和下一步。

缺少数据、图形类型或字段时，自然语言输入框仍可提交，系统以对话消息引导用户补齐条件，不创建可执行计划。已有 Agent 请求正在等待模型返回时，输入框暂时锁定以避免并发提交；切换项目、数据或图形会作废迟到响应。

## 3. 对话对象

### 3.1 用户与 Agent 消息

- 用户提交的原文必须持久显示为右侧用户气泡，提交后不得只清空输入框而不留记录；
- Agent 的理解、追问、拒绝、进度、失败和完成必须进入左侧时间线；
- 不显示内部推理、供应商请求正文、控制台日志或 renderer 参数；
- 对话正文只解释当前任务，详细数据和参数由嵌入对象按需展开。

### 3.2 常驻上下文条

Composer 上方持续显示本轮实际上下文，至少包括：

- 当前项目；
- 当前数据文件、工作表或数据块；
- 用户选择的图形类型；
- 当前 PlotDocument 与版本（若存在）；
- 当前作用对象与范围。

每个已实现的上下文项均可通过对应可见控件切换或移除；多数据上下文最多明确选择 8 个数据集。`@` 显式引用项目内对象属于后续能力，当前 Agent 不依赖该入口或不可见的跨项目记忆。

### 3.3 嵌入式卡片

对话中允许以下结构化对象，但不得把全部消息做成同样的卡片：

- 数据上传与导入结果；
- 图形选择；
- 必要追问；
- 字段绑定确认；
- 变更确认；
- 执行状态；
- 部分失败；
- 图形结果与导出结果；
- 版本比较与恢复。

## 4. 条件不足时的行为

| 缺失条件 | Agent 行为 | 可执行结果 |
|---|---|---|
| 没有数据 | 说明需要数据，并嵌入上传入口 | 不创建计划或项目版本 |
| 没有图形类型 | 要求用户从图形库明确选择，并嵌入选择入口 | 不猜图、不创建计划 |
| 字段角色不完整 | 展示缺失角色与可用候选，提出一个必要问题 | 不静默绑定 |
| 存在多个同等候选 | 展示最多三个清晰选项 | 用户选择后继续同一轮 |
| 请求超出共同能力 | 解释不支持的动作和保持不变的对象 | 返回 Unsupported，无副作用 |

## 5. 确认卡

任何创建图形或修改权威对象的 Agent 计划，在执行前必须展示具体影响，不能只列泛化动作名称。确认卡至少显示：

- 目标数据、图形、版本和作用范围；
- 图形类型；
- `角色 → 字段` 的完整映射；
- 将修改的标题、坐标轴、系列、图例、参数或 Profile 声明的数据标签；
- 当前会生成的 Matplotlib 预览，以及用户随后可单独请求的 Origin 原生项目导出；
- 必要警告、跳过项和不支持项；
- “确认并执行”“修改”“取消”三个明确动作。

字段绑定建议可以按需展开简短理由，例如字段名、数据类型、取值形状和图形角色要求；不得用未经校准的伪精确置信度替代依据。

## 6. 真实阶段反馈

### 6.1 显示原则

- 所有文案必须由真实 Agent、Core、TaskPlan 或 renderer 事件驱动，不用定时器伪造阶段；
- 计划生成前只能显示“整理上下文”“理解需求”“检查执行条件”等真实可知状态；
- 用户确认后，才可显示字段校验、数据准备、renderer、验证和保存状态；
- 当前阶段一旦可知即显示为单条状态，不用定时器制造额外过渡；后续如增加短阶段抑制，也不得隐藏长等待的真实当前阶段；
- 未知总时长使用非确定状态，不显示百分比或剩余时间；只有总数真实已知的批量任务显示 `已完成 / 总数`；
- 同一任务只更新一条执行消息，完成后折叠为摘要和“查看执行详情”，不把每个内部步骤堆成聊天消息。

### 6.2 用户可见阶段

允许的基础阶段文案包括：

- 正在整理当前数据和图形上下文…
- 正在理解你的要求…
- 正在检查执行条件…
- 正在校验字段绑定…
- 正在准备绘图数据…
- 正在调用 Matplotlib 渲染器…
- 正在调用 Origin 渲染器…
- 正在验证图形结构…
- 正在保存图形版本…

状态前使用一个克制的呼吸圆点。动画仅改变透明度和轻微缩放，周期约 1.4 秒；阶段切换采用 150–200 ms 淡入。`prefers-reduced-motion: reduce` 下取消呼吸与位移，仅保留静态状态和文本更新。

## 7. 停止、失败与恢复

- 运行中的任务提供“停止任务”；停止与执行完成后的“撤销”是不同操作；
- 任务失败必须说明失败阶段、稳定原因、已经完成的结果和可执行恢复动作；
- Matplotlib 成功而 Origin 失败时，保留 Matplotlib 结果，并允许只重试 Origin；
- 批量初次创建允许部分成功，成功项保留，失败项可以局部重试；
- 恢复不得重做已成功项，不续跑进程内部状态，不产生半成品版本；
- 用户切换项目、数据、图形或作用对象后，迟到的旧响应不得覆盖当前消息、计划或错误；
- 应用重启后，已提交结果恢复；运行中断的任务明确显示为“已中断”，由用户决定是否继续有效的未完成项。

错误必须出现在对应任务消息中；顶部通知只能作为辅助提醒，不能成为唯一错误载体。

## 8. 结果闭环

完成消息至少说明：

- 创建或修改了什么；
- 新的 PlotDocument ID 与版本；
- 成功的 renderer 与失败/跳过的目标；
- 重要警告；
- 可执行的“打开图形”“继续修改”“导出”“查看变更”“撤销本轮”。

同一权威对象可以在对话、项目资源库、聚焦编辑和版本历史中以不同视图呈现，但不得复制成相互漂移的状态。

当前图形作为上一轮已经完成的时间线对象呈现。用户继续修改、Agent 返回新阶段、出现确认卡或完成导出时，新内容必须追加到该图形之后；不得把“当前图”固定在消息流尾部，造成新消息反向出现在图形上方。

导出完成采用两层反馈：短时高显著提示负责让用户立即看见，时间线中的持久结果条负责后续查找。两者显示文件名；持久结果还显示可用的大小与内容哈希，并提供打开文件和打开所在文件夹。页面只接收已注册资源 ID，不接收本机绝对路径。

“编辑图形”进入聚焦编辑并默认打开参数检查器。面向当前发布范围的检查器只展示常规、系列、坐标轴和图例四类公共能力；控件直接产生强类型编辑动作，不通过自然语言关键词路由，也不承诺 Origin 专属且尚未验证的属性。

## 9. 撤销、重做与版本历史

- 每次成功的 Agent 或手动编辑都会创建新的 PlotDocument 版本；
- 结果消息提供“撤销本轮”，桌面提供 `Ctrl+Z` 撤销最近一次可撤销变更和 `Ctrl+Shift+Z` 重做；
- 撤销以逆动作生成新版本实现，不删除原历史；
- 当前通用撤销只覆盖能够从现有 PlotDocument 精确构造完整逆动作的基础标题文本、基础坐标轴、系列样式、基础图例和图形参数变更；计划包含字体、网格、图例列数/标题等尚无完整前态快照的高级参数时不显示“撤销本轮”，禁止部分回滚；
- 当前聚焦编辑支持当前版本与其直接父版本的真实预览比较。任意历史版本浏览、命名检查点和从历史分支创建后续版本属于后续能力；
- 当前撤销/重做栈属于本次桌面会话，项目重启恢复已提交的最新图形版本，但不恢复会话内 redo 栈；
- 创建图形、字段重绑、数据导入、批量创建和导出不纳入当前通用撤销；
- 正在运行的任务不可使用撤销替代停止；
- 数据导入、外部文件覆盖以及已经写出的 PNG、SVG、OPJU 不纳入通用撤销。项目内导出记录可以更新，但不得删除用户文件。

## 10. 后台任务

- 长任务离开当前对话后继续运行，任务中心显示运行、等待确认、部分成功、失败和完成数量；
- 当前任务中心展示权威 Task 及可用的停止动作；从任务项跳回原始用户消息和独立完成通知属于后续能力；
- Origin 任务继续服从串行资源约束，但界面必须说明“等待 Origin”而不是停在无意义的加载状态。

## 11. 本轮优先级

### P0，已实现，待正式黑盒确认

1. 上下文始终可见；
2. 确认卡展示具体变更；
3. 错误指出阶段、原因和恢复动作；
4. 停止、局部重试、部分成功保留；
5. 每轮形成结果闭环；
6. 缺少前置条件时仍可提交自然语言并由 Agent 引导；同一时刻只允许一个模型请求；
7. 真实阶段事件与减少动态效果。

### P1，本轮已实现范围，待正式黑盒确认

1. 最新 PlotDocument 恢复和相邻版本比较；
2. 撤销、重做和“撤销本轮”；
3. 当前作用对象与范围可见；
4. 同一权威对象在多视图保持一致；
5. 字段绑定与具体动作可核对；自动绑定理由解释仍待后续增强；
6. 长任务后台运行与已提交结果重启恢复；返回定位仍待后续增强。

### P2，本轮不实施

- `Ctrl+K` 上下文命令菜单扩展；
- `@` 项目对象引用；
- 直接恢复任意历史版本、任意版本浏览、命名检查点、历史分支与持久化 redo 栈；
- 任务完成通知和从任务中心跳回原消息；
- 大规模快捷键体系；
- 面向熟练用户的高级 Composer 操作；
- 个性化提示、复杂工作区布局和独立通知中心增强。

现有可见入口不得暗示这些 P2 能力已经完成。

## 12. 实施依赖与验收顺序

交互升级不能掩盖功能阻断。当前实施顺序固定为：

1. 已修复“确认映射并绘图 → Core 拒绝”的 JSON 集合契约问题；
2. 已完成代码级桌面回归和交互 P0/P1 的本轮实现范围；
3. 运行前端、Agent、Core、任务运行时和两个 renderer 的完整集成门禁；
4. 从正式 Windows Electron UI 重跑 34 图、编辑、撤销、导出、Origin 重开和重启恢复黑盒；
5. 只有第 4 步的原始 UI 与产物证据可以关闭本轮验收。

源码、单元测试或“执行过”不能替代正式 UI 与原始产物证据。

## 13. 最小验收矩阵

| 场景 | 通过标准 |
|---|---|
| 无数据发送自然语言 | 用户消息保留；Agent 返回上传引导；无计划、无版本 |
| 有数据但无图形 | Agent 嵌入图形选择入口；不猜图 |
| 条件齐全 | 展示具体字段绑定确认卡；确认前无副作用 |
| 正常执行 | 真实阶段按事件更新；完成后生成结果卡和新版本 |
| 快速执行 | 只显示真实状态，不显示虚假百分比、剩余时间或伪造阶段 |
| Matplotlib 成功、Origin 失败 | 保留预览；明确部分成功；只重试 Origin |
| 用户停止 | 不产生半版本；已提交边界保持；状态可理解 |
| 撤销与重做 | 对可逆编辑，`Ctrl+Z`/`Ctrl+Shift+Z` 和按钮一致；每次恢复产生新版本，原历史不被删除 |
| 切换上下文 | 旧响应不得覆盖新上下文；上下文条立即更新 |
| 应用重启 | 对话、最近图形版本和已提交结果恢复；中断任务不静默续跑；不要求恢复会话 redo 栈 |
| 减少动态效果 | 无呼吸/位移动画，阶段文本和可访问状态仍完整 |
