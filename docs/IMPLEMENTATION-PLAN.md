# PlotAgent 施工、测试与发布路线

> 状态：当前唯一交付顺序。本文规定从需求进入施工直到发布判定的先后关系；产品范围见 [PRD](./PRD.md)，测试覆盖见 [产品测试覆盖审计](./PLOTAGENT-PRODUCT-TEST-COVERAGE-AUDIT.md)，发布门槛见 [Beta 性能测试与发布门禁](./PERFORMANCE-TEST-RELEASE.md)。

## 1. 固定顺序

```text
范围确认
  → 启动与环境冒烟
  → 前端组件结构
  → 功能实现与切片测试
  → 样式设计与视觉验收
  → 全量确定性测试
  → 定向 Windows UI 测试
  → 冻结发布候选
  → 完整产品黑盒
  → SEQ-70
  → 发布判定
```

### 1.1 范围确认

- 先更新 PRD、产品决策、能力目录和验收口径，再动实现。
- 明确本轮新增、修改、删除和不做的能力；禁止一边施工一边扩大范围。
- 变更图类、字段合同、公开编辑参数或导出语义时，先更新独立产品期望，不从实现反推需求。
- 实现前必须把需求展开成完整的任务状态转换矩阵、能力矩阵和跨层追踪表；未冻结矩阵时不得用成功路径切片代替范围定义。

### 1.2 启动与环境冒烟

- 在开始 UI 施工前确认 Core、Electron、provider 配置和必要的 Origin 环境可启动。
- 冒烟只排除环境噪声，不代替功能测试。
- 启动异常未关闭时，不进行视觉验收或正式黑盒。

### 1.3 前端组件结构

- 先确定信息层级、时间线顺序、组件边界、状态归属和可访问语义。
- 组件只消费结构化产品状态；不得在前端解析自然语言或维护第二套领域状态。
- 这个阶段允许使用受控 demo 验证结构，但 demo 不是产品证据。

### 1.4 功能实现与切片测试

- 按一条可交付纵切实现：合同 → Core → Main/Preload → Renderer → 双后端/持久化。
- 每个切片同步补 Schema、类型、正反例、错误语义和受影响文档。
- 可见交互必须接真实状态；不得只补前端外观，也不得用补丁绕过领域合同。
- 暴露一个缺口时先审计其所属能力族和全部消费者，再统一修复；禁止只修当前图类、当前参数或当前状态而把同类缺口留到下一轮黑盒暴露。

### 1.5 样式设计与视觉验收

- 功能结构稳定后再统一排版、颜色、密度、动效和响应式细节。
- 涉及图形默认态或 renderer 的变化，先生成当前提交的视觉产物，由人工审查后才能冻结。
- 纯组件样式变化无需重跑 34 图 renderer；影响画布、导出或 Origin 的变化必须重跑受影响图类。

### 1.6 全量确定性测试

- 运行任务状态矩阵、能力矩阵、Python、TypeScript、Schema/codegen、lint、typecheck 和生产构建。
- 测试必须同时覆盖生命周期、能力声明、跨层传递和双后端执行，不能由同一份目录自证完整。
- 这一阶段不调用真实模型来替代确定性合同测试。
- 任务状态机必须对全部合法/非法转换、取消、重试、部分失败、恢复和重启做确定性穷举；模型非确定性只在其后的语义评测中验证。
- 公共能力必须按“全部正式图类 × 适用参数 × 双后端 × 保存/重开”生成或枚举测试，不能依赖少数代表图推断覆盖。

### 1.7 定向 Windows UI 测试

- 对本轮修改路径、历史高风险路径和错误恢复做正式 Electron 实测。
- 保存截图、对象 ID/版本、导出物和重启前后身份。
- 定向测试通过只允许进入冻结，不等于完整产品已经验收。

### 1.8 冻结发布候选

- 固定 commit、依赖、fixture、模型配置、Origin 版本和输出目录；工作树必须干净。
- 冻结后只允许修复阻断缺陷。任何产品代码改动都会形成新的候选并重跑受影响门禁。
- 测试说明只描述当前用户能力和证据规则，不硬编码过期提交或历史答案。
- 架构施工、模型适配和正式验收不得交叉推进；只有确定性矩阵、静态门禁和定向 UI 全绿后才能冻结候选并开始正式验收。
- 正式验收发现产品缺口后立即停止沿用旧候选结论；同类审计、修复和受影响门禁完成后，以新 commit 重新冻结。

### 1.9 完整产品黑盒

- 只从正式 Windows Electron 入口执行，不以源码、单测、静态页面或历史产物补证。
- 覆盖 34 图代表路径、Agent 任务、数据导入/处理、编辑、撤销重做、恢复、重启和三种导出。
- `PASS` 必须实际观察到预期；未执行为 `UNVERIFIED`，环境阻断为 `BLOCKED`，产品错误为 `FAIL`。

### 1.10 SEQ-70

- 在同一个冻结候选上从零运行真实模型评测，验证规划、对象/字段绑定、追问、工具、修复和恢复。
- SEQ-70 不替代 UI、renderer、Origin 或导出黑盒；它只证明冻结任务集上的 Agent 资格。

### 1.11 发布判定

- 汇总确定性门禁、视觉签名、Windows 黑盒、Origin fresh-reopen、SEQ-70 和 known issues。
- 关键范围必须为零 `FAIL`、零 `BLOCKED`、零应测 `UNVERIFIED`。
- 不得为了发布降低合同、忽略问题、沿用陈旧证据或把“已记录”写成“已通过”。

### 1.12 本轮施工教训形成的长期约束

本节不是复盘备注，而是后续每轮都必须遵守的执行约束：

1. **矩阵先于实现。** 先冻结状态、能力、后端、持久化和用户可见结果的完整交叉关系，再开始施工。
2. **同类缺口一次审完。** 单点失败只是审计入口；修复范围由能力族决定，不由当前失败样例决定。
3. **确定性与模型评测分层。** Core 状态、权限、幂等、副作用和错误恢复只由确定性测试证明；真实模型只证明语义理解和规划质量。
4. **冻结后再验收。** 黑盒和 SEQ-70 只针对同一干净候选；任何产品代码变化都会使受影响证据失效。
5. **不同证据不互相代替。** 单元测试、机械读回、视觉审查、正式 UI、真实模型评测和用户验收分别记账。
6. **不以发布为由降质。** 发现系统性问题时允许延长施工，但不允许忽略、缩窄合同或用补丁式特例换取表面全绿。

## 2. 变更后的最小回归原则

| 变更 | 必须重跑 |
| --- | --- |
| 纯文案或非结构样式 | 组件测试、可访问性检查、定向 UI |
| 时间线、确认卡、编辑器组件 | 前端全量、对应 Core 投影、定向 UI |
| Agent 合同或运行时 | 状态矩阵、Agent 全量、定向 UI、SEQ-70 |
| Profile/公共编辑能力 | 能力矩阵、编译器、前端目录、双后端、受影响 UI |
| 单图 renderer/Origin recipe | 该图 default/edited/dynamic/fresh、视觉审查、导出 |
| 共享 renderer/T1 适配器 | 所有受影响图类；无法精确界定时重跑 34 图 |
| 导入、存储或项目 schema | 导入 golden、迁移/拒绝、重启恢复、打包与 UI |
| 发布脚本或依赖 | 完整构建、安装包校验和发布门禁 |

## 3. 当前产品基线

- 34 张正式单图；不支持组合图或自由画布。
- Pi 是可替换 Agent 运行循环；Core 是任务、权限、确认、版本和执行权威。
- Matplotlib 与 Origin 使用独立 renderer；Origin 产物必须是原生可编辑 OPJU。
- 用户可从图形库明确选图，也可在自然语言中明确指定正式图类；存在实质歧义时 Agent 追问。
- 正式桌面当前不公开 WorkflowRecipe 保存/重放，也不公开独立文本标注。
- 项目 schema 当前为 v7；本机 v5/v6 工作区只允许代码已覆盖的事务性增量迁移，其他版本稳定拒绝。

## 4. 当前前端施工决策记录

本节记录为避免阻塞而由施工过程直接作出的取舍，最终统一视觉审计时必须向用户复述，不得把未采用方案隐藏为“没有考虑”。

| 决策 | 当前选择 | 未采用方案 | 取舍原因 |
| --- | --- | --- | --- |
| AI 界面参照 | 采用 Beautiful UI 的 Loading/Thinking、Approval、Task Rows、Chat、Prompt Bar、Diff/Table、Sidebar、Fine-tune Inspector 模式 | 复制参考站主题或组件源码 | 只需要成熟信息层级；PlotAgent 仍需自己的领域状态、Windows 桌面语义和科研数据对象 |
| 组件依赖 | 继续使用现有 React、Lucide 与 CSS token；复杂无障碍 primitive 出现实际需要时再单组件引入 | 整包引入 Tailwind/shadcn、assistant-ui 或另一套 design-system runtime | 全量迁移会扩大桌面包、样式和测试风险，不直接增加绘图能力 |
| 视觉方向 | 冷灰蓝工作台、深墨色主操作、纯白图表画布、单一蓝色焦点 | 默认灰白黑、深色/霓虹 AI 主题、绿色品牌底色 | 提高产品辨识度，同时让图形而非产品 chrome 保持视觉主角 |
| 组件边界 | 统一 Agent 消息原语；对话、确认、任务状态与结果继续消费现有结构化状态 | 重写时间线、引入第二套前端领域状态 | 现有时间线合同已通过确定性测试，视觉施工不应重做任务编排 |
| 测试范围 | 纯 UI 变化先跑前端全量与正式 Electron 定向测试 | 重跑全部 34 图 renderer/Origin | 当前变更不修改画布、PlotSpec、renderer 或导出语义；若后续触及这些范围再扩大回归 |
